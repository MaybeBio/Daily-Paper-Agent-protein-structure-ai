## 02 一句话总结

## 03 研究问题

- **具体问题**：如何构建一个抗体结构预测基准，使得训练集与测试集之间的泄漏可被量化、控制，并支持可复现的深度学习评估？
- **为什么重要**：抗体结构预测、抗体-抗原相互作用建模和设计领域的深度学习方法进展迅速，但不同研究之间的比较困难，因为训练集和测试集常独立构建，且仅靠时间截点无法防止训练-测试泄漏。泄漏会导致评估结果虚高，误导方法比较和领域进展判断。
- **现有方法为何不足**：现有基准（如 SAbDab 衍生的数据集）通常只提供结构数据，不提供泄漏控制机制；时间截点（temporal cutoff）只能防止未来数据进入训练集，但无法防止同源序列或相同抗体在不同时间点被重新解析并分入不同集合。
- **精确研究问题**：Can a versioned structural antibody benchmark with sequence-similarity-based leakage filtering and nearest-neighbor annotation enable reproducible and leakage-aware evaluation of deep-learning antibody structure prediction methods?

## 06 核心思想

### 1) 表面方法

SABLE 是一个版本化的抗体结构基准资源，包含：
- **固定训练集**：16,511 个实验结构条目
- **测试集**：327 个人工审核的实验结构条目 + 3,274 个高置信度、专利衍生的 AlphaFold3 模型（覆盖 476 个抗原）
- **泄漏控制**：测试候选结构在 AlphaFold3 时间截点之后选取，并用抗体和抗原序列相似性过滤器过滤
- **最近邻记录**：每个测试条目记录其与训练集的最近邻，允许用户量化剩余相关性
- **API 与指标**：Python/PyTorch API 和标准化基准指标

### 2) 核心洞察

[Analysis] 本文的核心洞察在于：**泄漏不是二元的（有/无），而是连续的（程度可量化）**。与其试图完全消除泄漏（这在结构生物学中几乎不可能，因为同一抗体家族天然共享序列和结构特征），不如**显式记录并暴露泄漏程度**，让用户自行决定如何分层评估。这一设计哲学将「泄漏」从隐藏的缺陷转变为可审计的元数据。

另一个洞察是：**时间截点 + 序列相似性过滤是互补的**。时间截点防止未来数据泄漏，序列相似性过滤防止同源数据泄漏，两者结合才能有效控制泄漏。

### 3) 可能的普适教训

[Analysis] 对于蛋白质结构相关计算研究，本文的设计模式可迁移为：
- **任何结构预测基准都应记录测试条目与训练集的最近邻相似度**，而非仅提供二元「是否泄漏」标签
- **版本化发布**是保证可复现评估的基础设施，而非可选项
- **专利数据库可作为测试集的补充来源**，因为专利序列通常不在公共训练数据中，天然降低了泄漏风险

## 07 方法总览

- **输入**：PDB 中的实验抗体结构、专利数据库中的抗体序列
- **输出**：版本化的 SABLE 基准资源（训练集 + 测试集 + 元数据 + API）
- **模块**：
  1. **训练集构建**：从 PDB 收集 16,511 个实验抗体结构条目
  2. **测试集构建**：327 个人工审核的实验结构 + 3,274 个 AlphaFold3 专利衍生模型
  3. **泄漏过滤**：抗体和抗原序列相似性过滤器
  4. **最近邻注释**：每个测试条目记录与训练集的最近邻
  5. **元数据与 API**：版本化发布，提供 CDR 注释、冗余标签、模型置信度字段
- **训练**：不涉及模型训练，仅提供数据资源
- **工具**：Python/PyTorch API
- **反馈回路**：不适用（非迭代方法）
- **假设**：
  - 序列相似性过滤能有效控制结构层面的泄漏
  - AlphaFold3 时间截点之后的专利衍生模型具有足够的结构置信度
  - 327 个人工审核测试条目足以代表抗体结构预测的评估需求

**文字流程**：
1. 从 PDB 收集实验抗体结构 → 构建训练集（16,511 条目）
2. 从专利数据库获取抗体序列 → 用 AlphaFold3 生成结构模型 → 筛选高置信度模型（3,274 个）
3. 人工审核测试候选结构 → 保留 327 个实验结构
4. 对测试候选应用序列相似性过滤（抗体 + 抗原）→ 排除与训练集高度相似的条目
5. 对每个测试条目计算并记录与训练集的最近邻相似度
6. 打包为版本化资源，提供元数据、CDR 注释、冗余标签、置信度字段
7. 发布 Python/PyTorch API 和标准化评估指标

## 11 结论正确解读

- **任务范围**：本文不提出新的预测方法，而是提供评估基础设施。其结论边界为：SABLE 是一个可用于抗体结构预测深度学习评估的版本化基准资源。
- **Oracle/真值输入**：测试集中的实验结构来自 PDB，AlphaFold3 模型来自专利序列预测。实验结构作为真值，AlphaFold3 模型作为补充测试数据。
- **端到端状态**：本文提供的是数据资源 + API，不涉及端到端模型训练或推理。
- **算力成本**：未提供。AlphaFold3 模型生成需要 GPU 资源，但具体成本未披露。
- **历史数据依赖**：训练集来自 PDB 历史积累，测试集在 AlphaFold3 时间截点后选取。
- **模型依赖**：AlphaFold3 用于生成专利衍生测试模型，其质量直接影响测试集可靠性。
- **最难情形**：本文未讨论最难情形。可推测：与训练集高度同源但通过过滤的测试条目可能是最难评估的情形。

**有边界的复述**：SABLE 提供了一个版本化的抗体结构基准，通过时间截点 + 序列相似性过滤控制泄漏，并通过最近邻记录使泄漏程度可量化。该资源适用于抗体结构预测、抗体-抗原相互作用建模和设计任务的深度学习评估，但其测试集规模有限，且依赖 AlphaFold3 模型质量。

## 14 学到什么

**Agent 提炼的知识候选**：

1. **泄漏量化设计模式**：将「泄漏」从二元标签转变为连续度量（最近邻相似度），允许用户分层评估。可迁移到任何蛋白质结构预测基准的构建中——不仅记录「是否泄漏」，更记录「泄漏程度」。

2. **时间截点 + 序列相似性双重过滤**：单一过滤机制不足以控制泄漏，组合使用时间截点和序列相似性过滤可互补覆盖不同泄漏来源。可迁移到分子对接、MD 模拟等任务的训练/测试划分中。

3. **专利数据库作为测试集补充**：专利序列通常不在公共训练数据中，天然降低泄漏风险。可迁移到蛋白质设计任务中，利用专利序列作为独立测试集。

4. **版本化发布基础设施**：固定版本的数据 + 元数据 + API 是保证可复现评估的关键。可迁移到任何需要长期维护的基准资源中。

5. **CDR 注释和冗余标签**：提供细粒度的功能区域注释（CDR）和冗余度标签，支持用户按需过滤。可迁移到抗体-抗原对接基准中，支持按 CDR 区域分层评估。

6. **标准化评估代码**：提供统一的数据加载和指标计算代码，减少不同研究间的实现差异。可迁移到结构预测、构象采样等任务的评估协议标准化中。

## 15 与已有知识连接

- **SAbDab（Structural Antibody Database）**：SAbDab 是抗体结构的主要数据库，本文的训练集很可能基于 SAbDab 或类似资源构建。SABLE 的贡献在于增加了泄漏控制和版本化机制，这是 SAbDab 未提供的。
- **AlphaFold3**：本文使用 AlphaFold3 生成专利衍生测试模型。AlphaFold3 是蛋白质结构预测的前沿方法，本文将其输出作为测试集的一部分，但经过时间截点和相似性过滤。
- **Temporal split 相关研究**：已有研究（如蛋白质工程中的时间划分）指出时间截点不足以防止泄漏，本文是对这一问题的直接回应。
- **[Analysis] 候选连接**：与「leakage-aware evaluation」相关的概念可连接到机器学习中的分布偏移（distribution shift）和数据泄漏（data leakage）文献。本文的最近邻记录类似于「leakage score」的概念，可连接到 fairness 和 robustness 评估中的分层分析（stratified analysis）方法。
- **[Analysis] 可迁移领域**：本文的版本化基准设计模式可迁移到蛋白质对接基准（如 DockQ 基准）、MD 模拟力场评估基准、蛋白质设计评估基准中。

## 16 研究想法

**Agent 生成的研究候选**：

1. **候选名称**：Leakage-Aware 蛋白质对接基准
   - **来源局限/观察**：本文仅覆盖抗体结构预测，未覆盖蛋白质-蛋白质对接。对接任务中训练/测试泄漏同样严重，且缺乏标准化基准。
   - **核心假设**：将 SABLE 的「最近邻记录 + 序列相似性过滤 + 版本化」设计模式迁移到蛋白质对接基准，可显著提高对接评估的可复现性和泄漏可控性。
   - **相对本文的增量**：扩展应用领域，从结构预测到对接；需处理对接特有的二聚体/多聚体序列相似性度量。
   - **初步方法**：基于 DockQ 或类似对接基准，构建版本化训练/测试集，记录每个测试复合物的最近邻训练复合物，提供分层评估 API。
   - **验证方式**：在多个对接方法（如 AlphaFold3 多聚体、RoseTTAFold 等）上比较泄漏感知评估与常规评估的结果差异。
   - **可能的失败模式**：对接复合物的序列相似性度量复杂，可能难以定义统一的「最近邻」标准。
   - **创新状态**：unverified

2. **候选名称**：结构相似性泄漏过滤器
   - **来源局限/观察**：SABLE 仅使用序列相似性过滤，未使用结构相似性过滤。结构预测任务中，结构相似的训练/测试对可能绕过序列过滤。
   - **核心假设**：在序列过滤之外增加结构相似性过滤（如 TM-score 阈值），可进一步降低泄漏，且不会过度减少测试集规模。
   - **相对本文的增量**：增加结构维度的泄漏控制，使基准更严格。
   - **初步方法**：对 SABLE 测试集与训练集进行全对全结构比对，计算 TM-score 分布，设定阈值并评估过滤效果。
   - **验证方式**：比较过滤前后测试集上的模型性能差异，检验是否存在高结构相似但低序列相似的对。
   - **可能的失败模式**：结构比对计算成本高，且结构相似的阈值选择可能引入主观性。
   - **创新状态**：unverified

3. **候选名称**：时间感知的抗体设计评估协议
   - **来源局限/观察**：SABLE 的测试集在 AlphaFold3 时间截点后选取，但未讨论训练集的时间范围。抗体设计任务中，时间泄漏（使用未来数据训练）可能更隐蔽。
   - **核心假设**：在抗体设计评估中引入严格的时间分层（如按 PDB 沉积日期划分），可更真实地反映模型在「未见未来」条件下的泛化能力。
   - **相对本文的增量**：将时间维度从测试集选择扩展到训练集构建，形成完整的时间感知评估协议。
   - **初步方法**：按 PDB 沉积日期将抗体结构分为时间桶，构建「过去训练、未来测试」的评估协议，并与随机划分对比。
   - **验证方式**：在多个抗体设计方法上比较时间划分与随机划分的性能差异。
   - **可能的失败模式**：时间划分可能导致训练集和测试集分布差异过大，评估结果受分布偏移影响而非模型能力。
   - **创新状态**：unverified

4. **候选名称**：抗体-抗原共折叠基准的泄漏控制扩展
   - **来源局限/观察**：SABLE 覆盖 476 个抗原，但未明确说明抗原-抗体复合物的共折叠评估。抗体-抗原共折叠预测是当前热点，泄漏控制更为复杂。
   - **核心假设**：在抗体-抗原共折叠基准中，需要同时控制抗体和抗原两侧的序列相似性，且复合物层面的相似性度量比单体更复杂。
   - **相对本文的增量**：将泄漏控制从单体扩展到复合物，处理双序列相似性约束。
   - **初步方法**：构建复合物级别的最近邻记录，同时考虑抗体和抗原的序列相似性，提供复合物层面的分层评估。
   - **验证方式**：在共折叠方法（如 AlphaFold3 多聚体）上比较复合物级泄漏控制与单体级泄漏控制的效果。
   - **可能的失败模式**：复合物层面的相似性度量可能过于严格，导致测试集规模过小。
   - **创新状态**：unverified
