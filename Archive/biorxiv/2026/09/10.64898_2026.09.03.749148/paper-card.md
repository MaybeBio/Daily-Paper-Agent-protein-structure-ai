## 02 一句话总结
为解决多工具软件栈冲突与算力门槛问题，本文提出 bioq——一个仅依赖 httpx 的 CLI 客户端，通过 bioq-services 网关将 38+ 个容器化药物发现工具统一暴露为自描述接口，在 serverless GPU 上按任务计费运行，使研究者与 coding agents 可从笔记本端一致访问全部工具。

## 03 研究问题
- **具体问题**：AI 药物发现工具各自携带不兼容的 GPU 软件栈，链式工作流需复现冲突环境并依赖数据中心级硬件，多数实验室无法承担。
- **为什么重要**：工具碎片化阻碍端到端自动化发现流程；算力门槛限制可及性。
- **现有方法为何不足**：现有工具无统一接口标准；本地部署需 CUDA/环境配置；云配置复杂；缺乏 agent 友好的自描述协议。
- **精确研究问题**：Can a dependency-light, self-describing CLI backed by a containerized service gateway provide uniform, agent-native access to a fleet of drug-discovery tools from a laptop without local model code or cloud configuration?

## 04 背景与发展脉络

## 06 核心思想
1. **表面方法**：一个依赖极轻的 CLI（仅 httpx），通过网关（bioq-services）调用 38+ 个容器化工具，在 serverless GPU 上按任务计费。
2. **核心洞察**：将「工具能力」与「执行环境」解耦——工具封装为容器，网关统一调度，CLI 自描述接口使 agent 可自动发现与调用；serverless 计费模式将算力成本从「持有」转为「按用付费」。
3. **可能的普适教训 [Analysis]**：在计算科学中，工具链的「接口一致性」与「环境可移植性」往往比单个算法精度更能决定实际采用率；面向 agent 的自描述协议是自动化科研的基础设施前提。

## 14 学到什么
**Agent 提炼的知识候选**：
1. **接口一致性设计**：为多工具系统设计统一 CLI 时，自描述协议（如输出 schema）可显著提升 agent 可调用性——可迁移到蛋白质结构预测/对接工具链的封装。
2. **环境解耦模式**：将工具封装为容器 + 网关调度，可避免本地环境冲突——适用于 MD 模拟、对接等需不同 GPU 栈的工具组合。
3. **按用付费算力**：serverless GPU 模式可降低中小实验室的算力门槛——可迁移到大规模构象采样或 MD 模拟的云端执行。
4. **Agent-native 设计**：面向编码代理的接口设计（自描述、无状态、可查询）是自动化科研工作流的关键——可迁移到 AlphaFold 批量预测或虚拟筛选的自动化。
5. **开源 + 自托管**：提供本地部署脚本可增强社区采用——适用于需要数据隐私的蛋白质设计项目。

## 15 与已有知识连接
- **相似**：与 Galaxy、DNAnexus 等平台类似，但更轻量、agent 导向；与 Snakemake/Nextflow 相比，更强调接口一致性而非工作流 DAG。
- **组合**：可与 AlphaFold、DiffDock、AutoDock Vina 等工具组合，作为统一前端；与 LLM-based agents（如 ChemCrow）结合，提供工具调用层。
- **冲突**：与「本地全栈部署」理念相悖，依赖云服务；与「单工具深度优化」相比，牺牲了工具特定功能。
- **可迁移领域**：蛋白质结构预测的批量推理、分子对接的虚拟筛选、MD 模拟的轨迹分析、序列设计的评估流水线。
- **候选方向**：将 bioq 模式扩展到蛋白质专用工具（如 AlphaFold3、Rosetta）的封装；或为 MD 模拟工具（GROMACS、OpenMM）提供统一 CLI。

   - **核心假设**：统一 CLI 可提升 AlphaFold、Rosetta、OpenMM 等工具的可组合性与 agent 可调用性。
   - **相对本文的增量**：聚焦蛋白质专用工具，增加结构比对、构象聚类等后处理模块。
   - **初步方法**：基于 bioq 架构，扩展容器舰队至蛋白质工具，定义统一输入/输出 schema。
   - **验证方式**：运行标准蛋白质结构预测任务，对比本地部署与 bioq 模式的延迟/成本。
   - **创新状态**：unverified

2. **名称**：AgentBench-Drug——药物发现 agent 工具调用基准
   - **来源局限/观察**：bioq 无实验评估，缺乏 agent 调用效率的量化指标。
   - **核心假设**：自描述接口可显著减少 agent 工具调用错误率与调试时间。
