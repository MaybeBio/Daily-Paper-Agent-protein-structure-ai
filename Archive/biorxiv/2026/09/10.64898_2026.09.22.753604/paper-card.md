## 02 一句话总结

本文提出 T-REX（Target-adaptive Rescue-Explore-eXploit）框架，用 LLM agent 在多个蛋白质生成模型与结构评估器之间做策略决策（rescue/explore/exploit），配合确定性控制器调度动作，以在有限计算预算下提升 de novo binder 设计的产出效率。

---

## 03 研究问题

- **具体问题**：面对日益增多的蛋白质设计工具（生成模型 + 结构评估器），如何在一个设计 campaign 中自动、高效地编排它们，使有限计算预算下的设计成功率最大化？
- **为什么重要**：AI 蛋白质设计工具生态快速膨胀，但缺乏统一的「指挥层」来协调多个互补工具；人工编排耗时且难以适应不同靶标。
- **现有方法不足**：现有工作多聚焦于单个模型的改进或简单流水线串联，缺乏**自适应策略调整**——即根据中间结果动态决定下一步动作（是挽救有希望的候选、探索新设置、还是沿有效路径深挖）。
- **精确研究问题**：Can an LLM-driven agentic controller, guided by accumulating design outcomes, outperform fixed or heuristic orchestration strategies in de novo binder design under a fixed compute budget?

## 06 核心思想

**1) 表面方法**：T-REX 是一个 agentic 框架，包含 LLM agent（负责推理与决策）和确定性控制器（负责验证与调度）。LLM agent 观察累积的设计结果，输出三类动作之一：rescue（挽救有希望的候选）、explore（探索替代设置）、exploit（沿有效路径深挖）；控制器确保动作合法并调度执行。

**2) 核心洞察**：蛋白质设计 campaign 的瓶颈不在单个模型的能力，而在**策略层**——如何根据中间反馈动态分配预算。LLM 的推理能力可被用于「阅读」累积结果并做出类人策略判断，而确定性控制器可防止 LLM 产生非法或低效动作。

**3) 可能的普适教训 [Analysis]**：在计算密集的蛋白质设计任务中，「何时停止、何时转向、何时深挖」的策略问题与「如何生成」同等重要；将 LLM 作为策略层 + 确定性逻辑作为执行层的混合架构，可兼顾灵活性与可靠性。

## 07 方法总览

- **输入**：靶标蛋白结构/序列、可用工具集（生成模型 + 评估器）、计算预算上限
- **输出**：设计候选 binder 的排序列表及每个候选的评估分数
- **模块**：
  1. LLM agent（策略决策）
  2. 确定性控制器（动作验证与调度）
  3. 工具集（多个蛋白质生成模型 + 结构评估器）
  4. 结果累积器（记录历史设计结果供 agent 参考）
- **训练**：未提及显式训练；LLM 为预训练模型，通过 prompt 引导决策
- **工具**：未具体列出（摘要仅称「multiple state-of-the-art protein generative models and structure evaluators」）
- **反馈回路**：设计结果 → 累积器 → LLM agent 推理 → 动作 → 工具执行 → 新结果
- **假设**：LLM 能基于文本化的设计结果做出有效策略决策；确定性控制器能有效约束 LLM 动作空间

**文字流程**：
1. 初始化：给定靶标与工具集，LLM agent 制定初始策略（如选择哪个生成模型、参数设置）
2. 执行：控制器调度选定的生成模型产生候选 binder
3. 评估：结构评估器对候选打分
4. 累积：结果写入累积器
5. 决策：LLM agent 读取累积结果，决定下一步动作（rescue/explore/exploit）
6. 循环：控制器验证动作合法性并调度执行，直至预算耗尽
7. 输出：最终候选列表

- **算力成本**：未提供具体数字；「finite compute budget」是框架设计的约束条件，但未量化。
- **历史数据依赖**：LLM agent 依赖「accumulating outcomes」做决策，即依赖 campaign 内部历史数据，不依赖外部训练数据。
- **模型依赖**：依赖预训练 LLM 的推理能力；不同 LLM 可能导致不同决策质量。
- **最难情形**：未讨论；推测为靶标高度复杂或工具集输出噪声大时，LLM 决策可能失效 [Analysis]。
- **不确定性**：未提供置信区间或统计显著性。
- **有边界的复述**：T-REX 在 de novo binder 设计场景中，通过 LLM agent 与确定性控制器的组合，实现了基于累积结果的自适应策略选择（rescue/explore/exploit），但具体性能提升幅度、适用靶标范围、计算开销等均未在摘要中量化。

## 14 学到什么

**Agent 提炼的知识候选**：

1. **策略层与执行层分离的架构模式**：将 LLM 作为「策略大脑」、确定性逻辑作为「执行骨架」的混合架构，可迁移到其他蛋白质设计任务（如结构预测的模型选择、MD 模拟的参数调度），用于在多个工具间做自适应分配。

2. **Rescue-Explore-Exploit 三动作框架**：这一策略分类可迁移到任何多工具蛋白质计算流水线——当中间结果出现「有希望但未达标」的候选时 rescue，当当前路径停滞时 explore，当某设置持续有效时 exploit。可作为通用 campaign 控制模板。

3. **累积结果作为 LLM 上下文的做法**：将设计历史以文本形式喂给 LLM 做决策，这一「结果 → 文本 → 推理 → 动作」的闭环可迁移到其他需要长序列决策的蛋白质计算任务（如多轮 MD 模拟的步长/力场选择）。

4. **对「工具编排」而非「单模型改进」的关注**：本文提示，在蛋白质设计生态成熟后，**编排层**可能是新的性能增长点——这一视角可迁移到结构预测（多模型集成调度）、构象采样（多方法切换）等方向。

5. **确定性控制器作为 LLM 安全网**：在蛋白质计算中引入 LLM 决策时，需配套确定性校验层防止非法动作（如超出预算、非法参数组合），这一设计模式可迁移到任何 LLM 辅助的蛋白质计算工作流。

**Agent 生成的研究候选**：

1. **候选名称**：T-REX 与人工专家编排的对照实验
   - **来源局限/观察**：摘要未提供任何对比实验，无法判断 LLM 策略是否优于人工或启发式
   - **核心假设**：在固定预算下，T-REX 的 LLM 策略在 binder 设计成功率上不劣于人工专家编排
   - **初步方法**：选取 5-10 个靶标，同一工具集下对比 T-REX、固定流水线、随机策略、2-3 名人类专家；记录成功率、预算消耗、时间成本
   - **验证方式**：成功率差异的统计检验（如 bootstrap 或贝叶斯检验）
   - **可能的失败模式**：LLM 策略在简单靶标上无优势，仅在复杂靶标上体现价值；或 LLM 推理延迟抵消计算节省
   - **创新状态**：unverified

2. **候选名称**：Rescue 动作的触发条件敏感性分析
   - **来源局限/观察**：摘要未定义 rescue 的具体触发条件（什么算「promising」？）
   - **核心假设**：rescue 触发阈值对最终产出有显著影响，且存在最优阈值区间
   - **初步方法**：固定 explore/exploit 策略，扫描 rescue 阈值（如评估分数百分位），测量产出曲线
   - **验证方式**：产出-阈值曲线的非单调性检验
   - **可能的失败模式**：产出对阈值不敏感，说明 rescue 动作冗余
   - **创新状态**：unverified

3. **候选名称**：LLM 策略器 vs 贝叶斯优化策略器在蛋白质设计中的对比
   - **来源局限/观察**：本文用 LLM 做策略决策，但未与传统优化方法（如贝叶斯优化）对比
   - **核心假设**：LLM 在需要「语义理解」的策略决策（如判断候选是否值得 rescue）上优于贝叶斯优化，但在纯数值优化上未必
   - **初步方法**：同一 campaign 任务下，分别用 LLM agent 和贝叶斯优化做策略器，对比产出
   - **验证方式**：产出差异 + 决策质量分析（如决策是否符合直觉）
   - **可能的失败模式**：LLM 在数值型决策上不稳定，贝叶斯优化更可靠
   - **创新状态**：unverified
