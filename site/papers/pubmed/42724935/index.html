8

Humanizing Antibodies and Nanobodies From Scratch With HuDiff.

Nan, Yang; Sun, Hongshuai; Zhang, Bo; Yang, Yue; He, Jianxin; Bai, Qifeng
Bio-protocol · 2026-09-11 · 全文(pmc) · 原文

提出HuDiff，一种基于自回归扩散模型的从头抗体/纳米抗体人源化方法，仅需CDR序列即可生成人源化抗体，属于蛋白质序列设计问题，方法创新且直接服务于蛋白质结构相关计算。

摘要

Antibody (Ab) and nanobody (Nb) humanization is essential for reducing immunogenicity in therapeutic applications. HuDiff is an adaptive autoregressive diffusion approach that generates humanized antibodies and nanobodies from scratch using only complementarity-determining region sequences as input, eliminating the need for preexisting human templates. The method follows a two-stage training pipeline: pretraining on human antibody sequences to learn framework region patterns, followed by fine-tuning on target-species sequences. HuDiff-Ab processes paired heavy and light chains for conventional antibodies, while HuDiff-Nb can incorporate a specialized inpainting mode to preserve critical nanobody framework residues. This protocol provides a complete step-by-step guide for implementing HuDiff, covering data preparation, model training, and sequence generation. Key features * Requires only CDR sequences as input and does not require human template selection. * Uses a two-stage training strategy, with pretraining on human antibody sequences and fine-tuning on target-species sequences guided by humanness scores. * HuDiff-Ab humanizes paired heavy and light chains simultaneously, whereas HuDiff-Nb provides an inpainting mode to preserve key framework residues. * Generates multiple diverse humanized candidates for downstream experimental screening.

摘要翻译

抗体（Ab）和纳米抗体（Nb）的人源化对于减少治疗应用中的免疫原性至关重要。HuDiff是一种自适应自回归扩散方法，仅使用互补决定区序列作为输入，从头生成人源化抗体和纳米抗体，无需预先存在的人类模板。该方法采用两阶段训练流程：先在人类抗体序列上进行预训练以学习框架区模式，随后在目标物种序列上进行微调。HuDiff-Ab处理常规抗体的配对重链和轻链，而HuDiff-Nb可整合专门的修补（inpainting）模式，以保留关键的纳米抗体框架残基。本协议提供了实施HuDiff的完整分步指南，涵盖数据准备、模型训练和序列生成。关键特征 * 仅需CDR序列作为输入，无需人类模板选择。 * 采用两阶段训练策略，在人类抗体序列上预训练，并在目标物种序列上以人源化评分指导微调。 * HuDiff-Ab同时人源化配对的重链和轻链，而HuDiff-Nb提供修补模式以保留关键框架残基。 * 生成多个多样化的人源化候选序列，供下游实验筛选使用。

02 一句话总结

HuDiff 是一种仅以 CDR 序列为输入、通过两阶段训练（人源抗体预训练 + 目标物种微调）的自回归扩散模型，从头生成完整人源化抗体/纳米抗体序列，无需人源模板，并用 AlphaFold2 验证生成序列的可折叠性。

03 研究问题

  • 具体问题: 如何仅从 CDR 序列出发，从头生成完整的人源化抗体和纳米抗体序列，避免传统 CDR-grafting 方法对人源模板的依赖和繁琐的反向突变（back-mutation）过程？
  • 为什么重要: 抗体/纳米抗体人源化是降低免疫原性、推进临床转化的关键步骤。传统方法依赖模板选择、结构知识和人工设计，效率低且难以自动化。
  • 现有方法不足: 模板依赖型方法（如 CDR grafting）需要合适的人源框架且常需反向突变；结构型方法（如 AbAdapt）需要 3D 结构；评分型工具（如 Sapiens、AbNatiV）只能评估不能生成。
  • 精确研究问题: Can a generative model produce full-length humanized antibody/nanobody sequences from CDR sequences alone, without human template selection, while preserving structural integrity?

06 核心思想

  1. 表面方法：两阶段训练的自回归扩散模型。预训练阶段学习人源抗体序列的框架区模式；微调阶段针对目标物种（小鼠、骆驼）序列进行适配。输入仅为 CDR 序列，输出为完整人源化序列。
  2. 核心洞察：CDR 序列决定了抗体的结合特异性，而框架区模式具有物种特异性。通过「人源预训练 + 目标物种微调」的两阶段策略，模型可以学会在保持 CDR 不变的前提下，将框架区「翻译」为人源化版本，从而绕开模板选择。
  3. [Analysis] 可能的普适教训：生成式模型在序列设计任务中的关键不是「从零生成」，而是「条件化重建」——给定功能关键区域（CDR），生成结构支持区域（框架）。这种「功能锚点 + 结构生成」的范式可迁移到其他蛋白质设计任务（如酶活性位点保留 + 支架重建）。

07 方法总览

  • 输入: IMGT 编号的 CDR 序列（抗体为重链+轻链 CDR，纳米抗体为单链 CDR）
  • 输出: 完整人源化抗体（重链+轻链）或纳米抗体序列，多个候选（默认 10 个）
  • 模块: 1. 数据准备模块：下载 release data，包含预训练和微调数据集（LMDB 格式） 2. 预训练模块：antibody_run.sh / nanobody_run.sh，在人源序列上学习框架模式 3. 微调模块：antibody_finetune.sh / nanofinetune_run.sh，在目标物种序列上适配 4. 生成模块：sample_for_anti_cdr.py / sample_for_nano_cdr.py，从 CDR 生成完整序列 5. 结构验证模块：AlphaFold2 (ColabFold) 预测 3D 结构，检查 pLDDT 和 ipTM
  • 训练流程: 预训练（人源序列）→ 微调（目标物种序列，纳米抗体需启用 inpainting mode）→ 生成（输入 CDR）→ 结构验证（AlphaFold2）
  • 工具: Python 3.9, PyTorch 1.13.0, CUDA 11.6, abnumber (IMGT 编号), AlphaFold2/ColabFold, PyMOL
  • 假设: CDR 序列足以决定结合特异性；框架区模式可通过学习获得；人源化序列应保持与原始序列相似的结构折叠
  • 文字流程: 用户准备 IMGT 编号的 CDR 序列 → 运行生成脚本（使用预训练 checkpoint 或自定义微调 checkpoint）→ 获得多个候选序列（CSV 格式）→ 用 AlphaFold2 预测结构 → 检查 pLDDT 和 ipTM 评估可折叠性 → 选择最优候选

11 结论正确解读

  • 任务范围: 本文是操作协议，验证了 HuDiff 的可复现性，而非新方法的性能验证。结论边界为「按照此协议可复现 HuDiff 的人源化生成流程」。
  • oracle/真值输入: 输入为 CDR 序列（IMGT 编号），这是唯一必需的序列信息。无需结构或模板。
  • 端到端状态: 流程覆盖「序列生成 → 结构验证」，但未包含湿实验验证（表达、亲和力、免疫原性）。因此「人源化成功」仅基于计算指标（T20、AbNatiV scores）和结构预测，而非功能性验证。
  • 算力成本: 推理成本低（2 分钟/序列 GPU），但预训练成本高（3-5 天集群），适合有 GPU 资源的实验室。
  • 历史数据依赖: 模型依赖人源抗体序列数据库和微调用的目标物种序列数据。对非模式物种（如牛、羊、猪）需自行微调。
  • 模型依赖: 依赖 AlphaFold2 作为结构验证工具，其预测准确性影响筛选结果。
  • 最难情形: 纳米抗体人源化中框架区保守残基的保留（需 inpainting mode）；非模式物种的微调数据不足。
  • 群体/领域边界: 适用于小鼠来源抗体和骆驼来源纳米抗体的人源化。对其他物种需重新微调。
  • 不确定性: 计算指标（T20、AbNatiV）与人源化成功（低免疫原性）之间的相关性未在本文中验证；结构预测不等于实验结构。

14 学到什么

Agent 提炼的知识候选： 1. 「功能锚点 + 结构生成」范式：以 CDR 为功能锚点、框架区为可生成区域，这种「条件化重建」思路可迁移到酶设计（保留活性位点、重建支架）、抗原设计（保留表位、重建骨架）等任务。 2. 两阶段训练策略：先在大规模人源序列上预训练学习通用框架模式，再在目标物种上微调适配。这种「通用预训练 + 领域微调」策略在蛋白质设计任务中具有普适性，尤其适用于数据稀缺的物种或蛋白家族。 3. Inpainting 模式用于保守残基保护：在生成过程中掩码关键残基（如纳米抗体 FR2 亲水残基），强制模型保留。这一机制可推广到任何需要保留特定功能/结构残基的序列生成任务。 4. AlphaFold2 作为生成后验证工具：将结构预测嵌入生成流程作为筛选环节，形成「生成 → 结构验证 → 筛选」闭环。这种「计算验证前置」策略可减少湿实验试错成本。 5. CDR-only 输入的极简设计：仅需 CDR 序列即可生成完整抗体，说明 CDR 携带了足够的结合信息。这种「最小输入」设计理念可启发其他序列设计任务的特征选择。

15 与已有知识连接

  • 相似方法：与基于扩散模型的蛋白质设计（如 RFdiffusion）同属生成式 AI 在蛋白质领域的应用，但 HuDiff 聚焦序列生成而非结构生成，且输入为 CDR 而非结构约束。
  • 组合方法：HuDiff 生成序列 + AlphaFold2 结构验证的组合，与「序列设计 → 结构预测 → 实验验证」的标准流程一致，可与其他结构预测工具（ESMFold、AlphaFold3）组合使用。
  • 对比方法：与判别式人源化评分工具（Sapiens、AbNatiV）互补——HuDiff 生成候选，评分工具筛选候选，可形成完整 pipeline。
  • 可迁移领域：CDR 驱动的框架重建思路可迁移到 TCR 人源化、纳米抗体亲和力成熟、双特异性抗体设计等免疫治疗相关任务。
  • [Analysis] 候选方向：HuDiff 的「CDR 输入 → 全序列生成」模式与「结构条件生成」（如给定 CDR 构象生成序列）结合，可能进一步提升生成序列的亲和力保持率。

16 研究想法

Agent 生成的研究候选：

  1. 候选名称: HuDiff-结构条件化扩展 - 来源局限/观察: HuDiff 仅以 CDR 序列为输入，未利用 CDR 的 3D 构象信息；部分 CDR 序列相同但构象不同的情况可能导致框架区生成不匹配。 - 核心假设: 将 CDR 的预测构象（如 AlphaFold2 预测的 CDR 环区结构）作为额外条件输入，可提高框架区生成的结构兼容性。 - 初步方法: 在 HuDiff 的生成过程中引入结构编码器，将 CDR 的 3D 坐标或距离矩阵作为条件；训练时使用 CDR 结构预测作为辅助输入。 - 验证方式: 对比有无结构条件的生成序列在 AlphaFold2 预测结构中的 CDR 构象保持率、框架区 pLDDT、以及实验验证的亲和力保持率。 - 创新状态: unverified

  3. 候选名称: 人源化序列的免疫原性实验验证 - 来源局限/观察: 本文仅提供计算指标（T20、AbNatiV），未验证生成序列的实际免疫原性降低效果。 - 核心假设: HuDiff 生成的人源化序列在体外/体内实验中表现出显著低于原始非人源抗体的免疫原性。 - 初步方法: 对表 3、表 4 中选定的候选序列进行 MHC-II 结合预测、树突状细胞激活实验、或 HLA 转基因小鼠免疫实验。 - 验证方式: 对比原始抗体与 HuDiff 人源化抗体的 T 细胞激活水平、抗药抗体（ADA）滴度。 - 创新状态: unverified

  4. 候选名称: HuDiff 与结构设计工具的集成 pipeline - 来源局限/观察: 本文仅用 AlphaFold2 做验证，未与结构设计工具（如 RFdiffusion、ProteinMPNN）集成。 - 核心假设: HuDiff 生成的人源化序列经结构设计工具进一步优化（如框架区稳定性增强），可获得更优的成药性。 - 初步方法: 将 HuDiff 输出作为 ProteinMPNN 的输入进行序列再设计，或与 RFdiffusion 结合进行结构-序列协同优化。 - 验证方式: 对比集成 pipeline 与 HuDiff 单独生成的序列在结构稳定性（pLDDT、RMSD）、humanness scores、可表达性方面的差异。 - 创新状态: unverified

  5. 候选名称: 生成序列的多样性-质量权衡分析 - 来源局限/观察: 本文默认生成 10 个候选，但未分析采样参数（如温度、top-p）对候选多样性和质量的影响。 - 核心假设: 存在最优采样参数区间，在该区间内生成候选的多样性与 humanness scores、结构质量达到最佳平衡。 - 初步方法: 系统变化采样温度、top-p 等参数，生成大量候选，计算多样性指标（序列相似性、CDR 构象聚类）与质量指标（T20、pLDDT）的 Pareto 前沿。 - 验证方式: 绘制多样性-质量 Pareto 曲线，确定最优参数区间。 - 创新状态: unverified
