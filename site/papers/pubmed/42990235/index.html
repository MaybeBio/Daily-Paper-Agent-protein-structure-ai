PHENOMS: Open-Source Software for Rust-Accelerated Hydrogen-Bond Analysis in Molecular Dynamics Simulations.

Novy, Brandon; Lin, Shu-Hang; Dey, Rishabh; Temple, Brenda; Hajicek, Nicole; Petrotchenko, Evgeniy V; Borchers, Christoph H; Sondek, John; Popov, Konstantin I
bioRxiv : the preprint server for biology · 2026-11-06 · 全文(pmc) · 原文

该文开发了Rust加速的开源软件PHENOMS，用于从分子动力学轨迹中分析蛋白质骨架氢键网络并与HDX-MS数据整合，属于蛋白质结构动态的计算分析工具，方法上结合MD模拟但侧重工程实现而非新算法。

摘要

Hydrogen-deuterium exchange mass spectrometry (HDX-MS) provides powerful insight into protein structure and dynamics, but interpretation of protection patterns at atomic resolution often requires complementary computational modeling. We present PHENOMS, an open-source Python package that integrates molecular dynamics trajectories with HDX-MS data to analyze backbone hydrogen-bond networks by tracking how individual hydrogen bonds and residue-residue contacts form, break, and reorganize throughout the simulations. This residue-level analysis can reveal local structural changes that may be missed by conventional global trajectory metrics. PHENOMS employs a multithreaded, Rust-accelerated computational engine that achieved an average 16-fold speedup (up to 100-fold) over widely used Python-based MD analysis packages in our benchmarks, while retaining individual hydrogen-bond resolution in every trajectory frame. We demonstrate PHENOMS through multiple retrospective case studies using published and in-house datasets, showing that it can recapitulate HDX-MS protection patterns, identify key residues that drive coordinated structural changes, and benchmark the computational efficiency of the approach. With automated quality-control workflows, PHENOMS provides a framework for integrating hydrogen-bond analysis with HDX-MS data or serves as a standalone, high-throughput tool for analyzing MD trajectories for broader applications in protein engineering, drug discovery, and structural biology.

摘要翻译

氢-氘交换质谱（HDX-MS）为蛋白质结构和动力学提供了强有力的洞察，但在原子分辨率下解读保护模式通常需要补充性的计算建模。我们提出了PHENOMS，一个开源Python包，它将分子动力学轨迹与HDX-MS数据整合，通过追踪模拟过程中单个氢键和残基-残基接触如何形成、断裂和重组，来分析骨架氢键网络。这种残基水平分析可以揭示传统全局轨迹指标可能遗漏的局部结构变化。PHENOMS采用多线程、Rust加速的计算引擎，在我们的基准测试中，相较于广泛使用的基于Python的MD分析包，实现了平均16倍（最高100倍）的加速，同时在每个轨迹帧中保持单个氢键分辨率。我们通过多个回顾性案例研究（使用已发表和内部数据集）展示了PHENOMS，表明它能重现HDX-MS保护模式，识别驱动协调结构变化的关键残基，并评估该方法的计算效率。凭借自动化质量控制工作流程，PHENOMS为将氢键分析与HDX-MS数据整合提供了一个框架，或作为独立的高通量工具，用于分析MD轨迹，以应用于蛋白质工程、药物发现和结构生物学等更广泛的领域。

02 一句话总结

本文开发了开源 Python 包 PHENOMS，通过 Rust 多线程加速引擎对 MD 轨迹逐帧执行 Baker–Hubbard 几何判据的氢键识别，计算残基对占用率与键持久性分数，并整合 HDX-MS 数据实现残基级保护模式对比，在基准测试中比 MDAnalysis 快 7–22 倍、比 MDTraj 快约 115 倍，且能复现 EGFR Δ747–749 突变体的已知 HDX-MS 动态变化。

03 研究问题

  • 具体问题：如何从 MD 模拟轨迹中高效、可复现地提取骨架氢键网络信息，并将其与 HDX-MS 实验保护模式进行残基级定量对比？
  • 为什么重要：HDX-MS 提供肽段级保护信息，但缺乏原子分辨率；MD 模拟可提供原子级动态细节，但氢键分析的计算成本高、工具碎片化、结果可比性差。整合两者可揭示配体结合、突变等引起的局部构象变化机制，对药物发现和蛋白质工程有直接价值。
  • 现有方法不足：(1) 主流工具（MDAnalysis、MDTraj）氢键识别速度慢，长轨迹大体系分析不现实；(2) 缺乏标准化流程（残基编号统一、复制间一致性检查、参数核验）；(3) 缺乏与 HDX-MS 数据直接对接的残基级打分体系；(4) 现有工具默认过滤低占用率氢键，可能丢失瞬态但功能重要的相互作用。
  • 精确研究问题：Can a Rust-accelerated, standardized hydrogen-bond analysis pipeline enable residue-level interpretation of HDX-MS protection patterns from MD trajectories at computational costs feasible for routine use?

06 核心思想

1) 表面方法：一个 Python 包，包含轨迹预处理（去 PBC、对齐、降采样）、Rust 多线程氢键检测引擎（Baker–Hubbard 判据）、占用率/持久性统计、图论网络分析、HDX-MS 对比模块，以及自动化 QC 和可视化。

2) 核心洞察： - 氢键网络的"关系性"信息：传统 RMSD/RMSF 只描述原子位置波动，丢失了残基间相互作用的"连接关系"。氢键占用率与持久性捕捉的是相互作用的稳定性与重组织，这直接对应 HDX 保护的物理机制——骨架酰胺氢的交换速率由其氢键参与状态决定。 - 保留全部氢键而非过滤：瞬态、低占用率的氢键可能在构象转换或变构调控中起关键作用，过滤会丢失这些信号。通过高效引擎使全量分析成为可能。 - 标准化是可比性的前提：残基编号统一、复制一致性检查、参数核验——这些"非核心"工程问题恰恰是跨研究可复现比较的关键。

3) 可能的普适教训 [Analysis]：在计算结构生物学中，"分析层"的工程化（标准化、QC、性能优化）与"采样层"（MD 本身）同等重要。许多科学结论的不可复现源于分析流程的碎片化而非采样不足。Rust/编译型语言加速 + Python 生态绑定的混合架构，是解决 Python 生态计算瓶颈的通用模式。

07 方法总览

  • 输入：MD 模拟轨迹（多种格式，经 MDTraj 读取）+ 拓扑文件；可选 HDX-MS 实验数据（肽段级保护值）
  • 输出：残基对氢键占用率矩阵、键持久性分数、残基级保护代理分数、氢键网络图（可导出 PDB B-factor 字段）、QC 报告
  • 核心模块： 1. 轨迹预处理：去 PBC、基于参考结构的旋转/平移拟合、可选降采样 2. Rust 氢键引擎（phenoms_hbond_rs）：多线程并行，对每个帧独立执行 Baker–Hubbard 几何判据（H–A 距离 < 2.5 Å，D–H–A 角 > 120°），输出扁平化数组 3. Polars 数据处理层：将逐帧氢键列表组织为占用率矩阵与持久性统计 4. SimulationSet：管理多个复制轨迹，执行残基编号标准化（基于序列比对）、QC 检查（RMSD 稳定性、参数一致性）、跨复制聚合 5. ComparisonSet：两组模拟（如 WT vs 突变体）的差异分析，生成共有/特有氢键列表、残基级差异打分 6. 图论分析：以残基为节点、氢键为边构建网络，识别局部子网络与重组织模式 7. 可视化与导出：网络图、B-factor 映射、QC 报告
  • 流程：轨迹 → 预处理 → Rust 引擎逐帧氢键检测 → Polars 聚合 → 占用率/持久性统计 → （可选）HDX-MS 对比 → 网络分析 → 可视化/导出
  • 技术栈：Python（主接口）、Rust（计算内核）、Polars（数据处理）、MDTraj（轨迹 I/O）、PyPI 分发、Docker 基准环境

09 关键公式符号

本文为软件工具论文，未提供形式化数学公式。核心判据为 Baker–Hubbard 几何条件（引用文献 23，未在文中展开公式）： - 氢键判定条件：氢-受体距离 d(H···A) < 2.5 Å 且供体-氢-受体角 θ(D–H···A) > 120° - 占用率（occupancy）：某氢键在轨迹中出现的帧数比例，即 O_ij = N_frames(键 i-j 存在) / N_total_frames - 持久性（persistence）：键连续存在的最长帧数（文中描述为 "longest continuous run of frames"） - QC 判据：ΔRMSD = |RMSD_block1 − RMSD_block2| / RMSD_block1 > 5% 标记潜在偏移；|slope| > 1×10⁻³ Å/帧 标记漂移

11 结论正确解读

  • 任务范围：本文验证的是 PHENOMS 作为分析工具的功能性（速度、标准化、HDX 对接能力），而非新生物学发现。EGFR 案例是"回顾性"验证，即用已知结果的系统测试工具能否复现。
  • oracle/真值输入：HDX-MS 实验数据（来自已发表文献）作为外部参照；MD 轨迹本身来自先前研究，非本文新采样。
  • 端到端状态：PHENOMS 是分析层工具，不涉及 MD 采样或结构预测。其输入是已完成的 MD 轨迹。
  • 算力成本：基准测试在共享 Docker 环境四线程下完成，100 帧 19,174 原子体系仅需 0.34 s，表明常规工作站可运行。
  • 历史数据依赖：EGFR 案例依赖已发表的 HDX-MS 数据；工具本身不依赖历史数据。
  • 模型依赖：氢键判据为 Baker–Hubbard 几何条件，不涉及机器学习模型。
  • 最难情形：未测试 intrinsically disordered proteins（IDP）或膜蛋白等复杂体系；未测试超长轨迹（>1,000 帧）的完整分析流程。
  • 不确定性：EGFR 案例为定性对比，未报告氢键分数与 HDX 保护值之间的定量相关性；基准测试未报告方差或多次运行的标准差。
  • 有边界的复述：PHENOMS 是一个开源工具，能在标准工作站上以比现有 Python 工具快 1–2 个数量级的速度完成 MD 轨迹的逐帧氢键分析，并提供标准化流程将结果与 HDX-MS 数据对接；在 EGFR 已知案例中可复现实验观察到的区域动力学变化，但其生物学发现能力尚未在前瞻性场景中验证。

14 学到什么

Agent 提炼的知识候选：

  1. Rust + Python 混合架构模式：将计算密集内核（逐帧几何判断）用 Rust 实现，通过 Python 绑定暴露接口，数据层用 Polars 管理。这种模式可迁移到任何需要高性能逐帧分析的 MD 后处理工具（如 RMSD 矩阵计算、接触图分析、水桥分析）。

  2. "保留全部事件"而非过滤的设计哲学：PHENOMS 刻意保留所有帧的完整氢键记录，而非像 MDTraj 那样默认过滤低占用率键。这启示：在后处理分析中，过滤阈值可能丢失瞬态但功能重要的信号；性能优化应服务于"全量分析"而非"加速过滤"。

  3. 残基编号标准化是跨状态比较的前提：通过序列比对将不同变体的残基编号映射到共同参考系，这是 WT vs 突变体、apo vs 配体结合比较的关键预处理步骤。可迁移到任何涉及变体比较的 MD 分析流程。

  4. QC 自动化作为可复现性基础设施：RMSD 稳定性检查（末 20% 分段比较 + 斜率阈值）和参数一致性核验，将"轨迹是否平衡"的判断从人工目检转为自动化标记。这种"QC 即基础设施"的思路可推广到其他 MD 分析工具。

  5. HDX-MS 对接的残基级代理分数：将 MD 氢键占用率/持久性转化为残基级保护代理分数，并导出为 PDB B-factor 字段，实现计算与实验数据的直接可视化对比。这一"代理分数 + 结构注释"模式可迁移到其他实验-计算对接场景（如交联质谱、突变扫描）。

  6. 图论网络分析揭示协同重组织：将氢键数据构建为残基级网络，识别局部子网络，可捕捉单个键分析遗漏的协同变化。可迁移到蛋白质构象变化、变构通路分析。

15 与已有知识连接

  • Baker–Hubbard 几何判据：本文使用的氢键判定标准（H–A 距离 < 2.5 Å，D–H–A 角 > 120°）源自 Baker & Hubbard 1984 年的经典工作（Prog Biophys Mol Biol），是 MD 氢键分析的事实标准之一。PHENOMS 与 MDTraj 使用相同判据，与 MDAnalysis 默认判据（D–A 距离 < 3.0 Å，角 > 150°）不同——这解释了部分氢键数量差异。
  • HDX-MS 与 MD 整合：本文引用的前期工作（文献 5–12）建立了 HDX 保护与 MD 氢键占用率相关的框架。PHENOMS 是对这一框架的工程化实现。类似思路可见于 HDXer、DynamXL 等工具，但 PHENOMS 的差异化在于全量保留 + 图论分析 + Rust 加速。
  • EGFR 突变研究：Δ747–749 是 EGFR 外显子 19 缺失突变，L858R 是外显子 21 点突变，均为 NSCLC 常见驱动突变。van Alderwerelt van Rosenburgh 等人的 HDX-MS 研究（文献 20）提供了本文的验证参照。
  • 与 AlphaFold 等 AI 方法的关系：本文引言明确指出 AI 结构预测对配体诱导或突变引起的细微扰动、以及 intrinsically disordered regions 的预测仍不可靠，MD + HDX 整合是互补路径。这与当前"AI 预测 + MD 精化"的主流趋势一致。
  • 可迁移领域：PHENOMS 的"全量事件保留 + 图论网络 + 实验数据对接"模式，可迁移到蛋白质-配体相互作用分析（对接后 MD 验证）、蛋白-蛋白界面分析、以及共价修饰（如磷酸化）引起的构象重组织研究。

16 研究想法

Agent 生成的研究候选：

  1. 候选名称：PHENOMS-ΔG：将氢键网络重组织映射为自由能变化的定量框架 - 来源局限/观察：PHENOMS 目前提供定性/半定量的占用率与持久性分数，但未将氢键网络变化转化为热力学量。EGFR 案例仅定性复现 HDX 模式。 - 核心假设：氢键占用率变化与残基级自由能变化之间存在可学习的映射关系，可通过 Boltzmann 加权或机器学习回归建立。 - 初步方法：在 PHENOMS 输出基础上，对每个残基计算 Δoccupancy 和 Δpersistence，结合 MM-PBSA 或伞形采样得到的参考自由能数据训练回归模型；输出残基级 ΔΔG 图谱。 - 验证方式：用已知突变（如 EGFR L858R、TP53 热点突变）的实验 ΔΔG 数据验证预测精度。 - 创新状态：unverified

  2. 候选名称：PHENOMS-IDP：针对 intrinsically disordered proteins 的氢键网络动态分析模块 - 来源局限/观察：本文引言承认 AI 方法对 IDP 预测不可靠，但 PHENOMS 的验证案例（EGFR）是折叠良好的激酶结构域。IDP 中氢键网络高度瞬态、空间分散，现有 Baker–Hubbard 判据可能不适用。 - 核心假设：IDP 的构象系综中，瞬态氢键的"出现-消失"模式（而非占用率）携带功能信息，可通过时间序列分析提取。 - 初步方法：扩展 PHENOMS 引擎输出逐帧氢键时间序列，计算氢键寿命分布、转移概率矩阵、以及氢键网络的时间聚类；与 NMR 化学位移扰动或 smFRET 数据对比。 - 验证方式：用已知 IDP（如 p53 N 端、α-synuclein）的公开 MD 轨迹和实验数据验证。 - 创新状态：unverified

  3. 候选名称：PHENOMS-AF：AlphaFold 结构系综的氢键网络一致性分析 - 来源局限/观察：AlphaFold 等 AI 方法输出单一结构或有限系综，缺乏动态信息；但 pLDDT 分数低的区域可能对应构象异质性。PHENOMS 的氢键网络分析可量化这些区域的"氢键冲突"。 - 核心假设：AlphaFold 预测结构中 pLDDT 低的区域，其氢键网络在几何上不满足 Baker–Hubbard 判据的比例显著高于高置信区域，可作为结构可信度的补充指标。 - 初步方法：对 AlphaFold 预测结构运行 PHENOMS 的静态模式（单帧氢键检测），计算残基级"氢键满意度"分数，与 pLDDT 做相关性分析。 - 验证方式：用 PDB 中高分辨率晶体结构与对应 AlphaFold 预测对比，检验氢键满意度是否能区分正确/错误预测区域。 - 创新状态：unverified

  4. 候选名称：PHENOMS-Lig：配体结合诱导的氢键网络重组织指纹 - 来源局限/观察：PHENOMS 的 ComparisonSet 支持两组比较（如 WT vs 突变），但未专门针对 apo vs holo 状态设计。配体结合引起的氢键重组织是药物设计的关键信息。 - 核心假设：配体结合诱导的氢键网络重组织具有"指纹"特征，可区分正构/别构结合模式，并预测结合亲和力。 - 初步方法：对 apo 和 holo MD 轨迹运行 PHENOMS，生成氢键网络差异矩阵；用图编辑距离或网络嵌入方法量化重组织程度；与实验结合亲和力做回归。 - 验证方式：用公开的配体结合 MD 数据集（如 DUD-E 子集）验证。 - 创新状态：unverified

  5. 候选名称：PHENOMS-Bench：氢键分析工具的标准化基准套件 - 来源局限/观察：本文基准仅对比了 MDTraj 和 MDAnalysis，且未提供方差统计。领域内缺乏统一的氢键分析基准。 - 核心假设：不同氢键分析工具（PHENOMS、MDTraj、MDAnalysis、VMD、PyMOL）在相同输入下结果存在系统性差异，标准化基准可揭示并改善工具间一致性。 - 初步方法：构建包含多种蛋白大小、轨迹长度、力场类型的基准数据集；统一氢键判据参数；报告各工具的结果差异、内存占用、耗时。 - 验证方式：发布基准套件并邀请社区参与扩展。 - 创新状态：unverified

  • Assessment boundary Scientific claims, methodological soundness, benchmark validity, and software utility as presented in the provided text

  • Visible evidence base Text descriptions of benchmarks (Table 1, Table S1 referenced but not visible), biological case study descriptions (Fig. 2 referenced but not visible), software architecture descriptions, and availability statements

Reviewer

  • Overall assessment The manuscript describes a potentially useful software tool for hydrogen-bond analysis in MD simulations, with a plausible design and a clear motivation rooted in HDX-MS interpretation. However, the provided text alone does not establish the core claims. The benchmark results are only described narratively with no visible data tables or figures, the biological validation is qualitative and lacks statistical rigor, and several methodological details are insufficiently specified. The software availability and reproducibility infrastructure are commendable, but the scientific case as presented is incomplete.
  • Who would be interested in the results, and why Computational structural biologists, HDX-MS practitioners seeking atomistic interpretation of protection data, and researchers developing or using MD analysis tools. The performance claims, if substantiated, would interest those analyzing large trajectories or many replicates. The integration of HDX-MS with MD analysis addresses a genuine need in the field.
  • Major Strengths The software addresses a real methodological gap by linking HDX-MS protection patterns to atomistic hydrogen-bond dynamics. The Rust-accelerated design is a sensible approach to a known performance bottleneck. The emphasis on reproducibility, including unit tests, Docker workflows, and Zenodo deposition, is exemplary. The focus on per-frame hydrogen-bond resolution rather than filtered or averaged results is scientifically defensible.
  • Major Concerns The benchmark claims are not verifiable from the provided text. The biological validation is qualitative and does not demonstrate statistical significance or quantitative agreement with experimental data. The quality control criteria are described but their sensitivity and specificity are not evaluated. The comparison with MDAnalysis uses different hydrogen-bond definitions, confounding the performance comparison. The manuscript does not describe how the residue-level protection scores are calibrated or validated against experimental HDX-MS data.
  • Minor Comments The abstract claims an average 16-fold speedup and up to 100-fold, while the introduction claims 7- to 22-fold over MDAnalysis and up to ~115-fold over MDTraj, and the results section reports 11-fold and 115-fold for the full system. These numbers are not internally consistent. The description of the quality control module is detailed but the thresholds appear arbitrary without sensitivity analysis. The statement about the "reproducibility crisis" is supported by citations but the connection to PHENOMS is somewhat tangential. The manuscript would benefit from a clearer statement of what is new relative to the authors' prior publications (references 11, 12, 16, 24).
  • Technical failings that need to be addressed before the case is established The benchmark data must be presented in full. The biological case studies need quantitative comparison with experimental HDX-MS data, including appropriate statistical measures. The hydrogen-bond definition used by PHENOMS must be compared with MDAnalysis under matched conditions to support the performance claims. The protection score calculation needs explicit mathematical definition and validation.
  • Assessment against Nature-style criteria Originality: moderate. The concept of linking HDX-MS to MD hydrogen-bond analysis is not new, and the authors cite prior work in this direction. The Rust acceleration is an engineering contribution rather than a conceptual advance. Scientific importance: potentially significant for the HDX-MS and MD communities, but the demonstrated impact is not yet established. Interdisciplinary readership: the tool bridges computational chemistry and experimental biophysics, which could attract a broad audience, but the current presentation is heavily software-focused. Technical soundness: cannot be fully assessed without the missing data; the described architecture is reasonable but the validation is insufficient. Readability for nonspecialists: the manuscript is generally clear but assumes familiarity with both HDX-MS and MD analysis; the software-oriented sections may be dense for experimentalists.
  • Recommendation posture Currently not established from the provided evidence. The software may be useful and the approach is sound, but the core claims of performance and biological validity require the missing data and additional validation before the case is convincing.
