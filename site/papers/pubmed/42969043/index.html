InterPro: the protein sequence classification resource in 2027.

该文介绍InterPro蛋白质序列分类资源2027年更新，虽涉及AlphaFold结构整合和深度学习覆盖提升，但核心是数据库资源而非蛋白质结构计算建模方法创新。

摘要

InterPro (https://www.ebi.ac.uk/interpro) is a freely accessible resource for the classification of protein sequences. It integrates predictive models, known as signatures, from multiple member databases to classify sequences into families and to predict the presence of domains and functionally important sites. The InterPro database provides annotations for hundreds of millions of sequences, ensuring extensive coverage of UniProtKB, the standard repository of protein sequences, and includes mapping to several other major resources, such as Gene Ontology, the Protein Data Bank in Europe (PDBe), and the AlphaFold Protein Structure Database. In this publication we report on the status of InterPro (version 110.0), detailing new developments in the database, its associated web interface, and software. Notable updates include InterPro-N, a deep-learning method that increases sequence coverage of UniProtKB to over 90%; the transition from InterProScan 5 to the completely re-engineered InterProScan 6; the integration of structure-based domain classifications and predicted structures from AlphaFold; a redesigned protein viewer offering a concise summary view; and a new Model Context Protocol (MCP) server that allows AI assistants to query InterPro programmatically. Over the past two years, 9484 new InterPro entries have been created, bringing the total to 54 922. InterPro data, software and tools are freely available.

摘要翻译

InterPro (https://www.ebi.ac.uk/interpro) 是一个可自由访问的蛋白质序列分类资源。它整合了来自多个成员数据库的预测模型（称为签名），用于将序列分类为家族，并预测结构域和功能重要位点的存在。InterPro数据库为数亿条序列提供注释，确保对UniProtKB（蛋白质序列的标准存储库）的广泛覆盖，并包含到其他主要资源的映射，如基因本体论、欧洲蛋白质数据银行（PDBe）和AlphaFold蛋白质结构数据库。在本出版物中，我们报告了InterPro（版本110.0）的状态，详细介绍了数据库、其相关网页界面和软件的新发展。显著更新包括InterPro-N，一种深度学习方法，将UniProtKB的序列覆盖率提高到90%以上；从InterProScan 5过渡到完全重新设计的InterProScan 6；整合基于结构域的分类和来自AlphaFold的预测结构；重新设计的蛋白质查看器，提供简洁的摘要视图；以及一个新的模型上下文协议（MCP）服务器，允许AI助手以编程方式查询InterPro。在过去两年中，创建了9484个新的InterPro条目，使总数达到54 922。InterPro数据、软件和工具均可自由获取。

03 研究问题

  • 具体问题：如何扩展 InterPro 对蛋白质序列的注释覆盖率，同时提升注释效率、整合结构信息并适应 AI 时代的数据访问需求？
  • 为什么重要：InterPro 是蛋白质序列功能注释的核心资源，支撑 UniProtKB、Gene Ontology、PDBe 等多个主要数据库的注释工作。随着测序数据爆炸式增长，传统基于 HMM 的 signature 匹配方法覆盖率有限（约 80%），大量序列无法获得注释；同时 AlphaFold 等结构预测工具的普及使得结构信息成为注释的重要补充。
  • 现有方法为何不足：传统 InterPro 依赖各成员数据库的 signature（如 HMM、profile、fingerprint），这些方法对远源同源序列的检测能力有限，导致约 20% 的 UniProtKB 序列无法被注释。此外，InterProScan 5 的架构难以适应大规模并行计算需求。
  • 精确研究问题：Can a deep-learning-based classifier (InterPro-N) combined with structural information from AlphaFold and a re-engineered scanning pipeline (InterProScan 6) achieve >90% sequence coverage of UniProtKB while maintaining annotation quality and enabling programmatic access for AI assistants?

06 核心思想

1) 表面方法： - 开发 InterPro-N，一个基于深度学习的序列分类器，用于补充传统 signature 匹配 - 完全重构 InterProScan 6 扫描流水线 - 将基于结构的域分类（如 CATH/SCOP 相关分类）和 AlphaFold 预测结构整合到注释流程 - 开发 MCP (Model Context Protocol) server 使 AI 助手可编程查询 InterPro - 新增 9,484 个 InterPro entries，总数达 54,922

2) 核心洞察： - 深度学习序列表示（如 protein language model embeddings）能捕获传统 HMM 无法检测的远源同源关系，从而显著提升覆盖率 - 结构信息（尤其是 AlphaFold 预测结构）可作为序列分类的补充证据，提高注释可靠性 - 数据库资源需要主动适配 AI 时代，通过 MCP 等协议让 AI 助手直接访问，而非仅提供网页/API

3) 可能的普适教训 [Analysis]： - 对于蛋白质结构相关计算研究，将「序列 → 结构 → 功能」的推理链条显式编码到注释流程中，比单纯依赖序列特征更鲁棒 - 深度学习模型与传统基于物理/进化的方法（HMM、结构比对）互补，而非替代——InterPro-N 是「补充」而非「替换」signature 方法 - 数据库/工具资源需要将「AI 可访问性」作为一等公民设计，MCP server 是这一趋势的代表

07 方法总览

  • 输入：蛋白质序列（UniProtKB 全库）、AlphaFold 预测结构（来自 AlphaFold DB）
  • 输出：蛋白质家族分类、结构域注释、功能位点预测、GO 注释映射
  • 核心模块： 1. InterPro-N：深度学习分类器，基于序列 embeddings 预测 InterPro entries 2. InterProScan 6：重构的扫描流水线，整合传统 signature 匹配 + InterPro-N + 结构比对 3. 结构整合模块：将 AlphaFold 预测结构用于基于结构的域分类 4. MCP server：提供标准化的 AI 助手查询接口 5. Web 界面：重新设计的蛋白质查看器，提供简洁摘要视图
  • 训练：InterPro-N 的训练数据、架构细节未在摘要中提供
  • 假设：深度学习序列表示能捕获传统 signature 方法遗漏的同源关系；结构信息能提升注释准确性
  • 流程：序列输入 → InterProScan 6 并行执行 signature 匹配 + InterPro-N 预测 + 结构域比对 → 整合结果 → 输出家族/结构域/位点注释 → 通过 Web/MCP/API 分发

11 结论正确解读

  • 任务范围：本文结论仅适用于 InterPro 数据库的序列分类覆盖率提升，不涉及注释准确性、生物学功能验证等。
  • oracle/真值输入：InterPro-N 的训练和评估依赖 InterPro 现有 entries 作为标签，这些标签本身来自各成员数据库的 signature 匹配，存在标签噪声可能。
  • 端到端状态：InterPro-N 是「补充」而非「替代」传统方法，端到端流程仍依赖 signature 匹配 + 深度学习 + 结构比对的组合。
  • 算力成本：未提供 InterPro-N 的训练/推理算力需求。
  • 历史数据依赖：InterPro-N 的训练数据来自历史注释，可能对新兴蛋白家族（如新病毒蛋白）检测能力有限。
  • 模型依赖：InterPro-N 的具体架构（如是否基于 ESM2 等 protein language model）未披露。
  • 最难情形：覆盖率提升主要针对「此前无法注释」的序列，这些序列可能是远源同源、孤儿序列或新折叠，InterPro-N 在这些情形下的精度未报告。
  • 群体/领域边界：结论基于 UniProtKB 的覆盖，不适用于非标准蛋白（如人工设计蛋白、非天然氨基酸）或宏基因组新序列的泛化性。
  • 不确定性：未提供置信区间、错误率或人工评估结果。

有边界的复述：InterPro 2027 版本通过引入深度学习分类器 InterPro-N，将 UniProtKB 序列的注释覆盖率从约 80% 提升至 90% 以上，同时完成扫描流水线重构和结构信息整合，但具体精度、算力成本和模型细节未在本文中披露。

14 学到什么

Agent 提炼的知识候选：

  1. 深度学习序列分类器作为传统 HMM 的补充层：InterPro-N 展示了 protein language model embeddings 或类似深度表示能捕获 HMM 无法检测的远源同源关系。对于蛋白质结构预测/构象采样课题，可借鉴「深度表示 + 传统方法」的混合架构——例如用 ESM2 embeddings 作为 MSA 构建的补充，或用于构象采样的初始 seeding。

  2. 结构信息作为序列分类的交叉验证信号：将 AlphaFold 预测结构整合到注释流程，意味着「序列 → 结构 → 功能」的推理链可以显式编码。对于分子对接或 MD 模拟课题，可借鉴「预测结构 + 实验结构」的联合使用策略，例如用 AlphaFold 结构作为对接初始构象，再用 MD 精修。

  3. MCP server 作为 AI 可访问数据库的范式：InterPro 通过 MCP 协议让 AI 助手直接查询，这对蛋白质结构研究有直接启示——未来可构建「结构数据库 MCP server」，让 LLM 直接查询 PDB、AlphaFold DB 或本地 MD 轨迹，实现 AI 驱动的结构分析工作流。

  4. 覆盖率 vs 精度的权衡意识：InterPro 追求覆盖率提升，但未报告精度。在蛋白质结构预测/设计中，类似权衡普遍存在——例如用更宽松的过滤条件提升构象覆盖率但引入噪声构象。需要显式报告并权衡。

  5. 数据库资源的「AI 原生」设计：InterPro 2027 将 AI 可访问性作为核心功能（MCP server），而非事后 API。对于结构生物学工具开发，应从一开始就设计 LLM 友好的接口（如结构化输出、标准查询协议）。

15 与已有知识连接

  • InterPro 历史版本：InterPro 是蛋白质序列分类的长期资源（~20 年历史），本文是 2027 年度更新。此前版本（如 2023, 2025）的更新报告发表于 NAR 数据库专刊，可对比查看覆盖率变化趋势。
  • Pfam/SUPERFAMILY：InterPro 整合了 Pfam 等成员数据库，Pfam 的 HMM 方法学与 InterPro-N 的深度学习方法形成对比。
  • AlphaFold DB：本文整合 AlphaFold 预测结构，与 AlphaFold Protein Structure Database (Varadi et al., 2024) 直接相关。
  • Protein language models：InterPro-N 很可能基于 ESM2 或 ProtTrans 等 protein LM embeddings（需全文确认），与 Lin et al. (2023) ESM2 工作相关。
  • MCP (Model Context Protocol)：由 Anthropic 于 2024 年提出的协议，本文是其在生物信息学数据库中的早期应用之一。
  • CATH/SCOP 结构域分类：本文「基于结构的域分类」可能涉及 CATH 或 SCOP 的映射，与 Orengo 组（本文作者之一）的工作直接相关。
  • 本课题方向：对于蛋白质结构预测/构象采样研究，InterPro-N 的「深度表示 + 传统方法」混合策略可迁移至「AlphaFold + MD 精修」或「ESM embeddings + 物理势函数」的混合管线设计。

16 研究想法

Agent 生成的研究候选：

候选 1：基于 protein LM embeddings 的构象空间导航 - 来源局限/观察：InterPro-N 证明深度序列表示能捕获远源同源关系；类似地，蛋白 LM embeddings 可能编码构象偏好信息，可用于引导构象采样。 - 核心假设：ESM2 embeddings 的隐空间距离与构象相似度（如 TM-score）存在相关性，可用于构象采样的初始 seeding 或降维可视化。 - 相对本文的增量：将 InterPro-N 的「序列分类」思路扩展到「构象生成」，从离散标签预测到连续构象空间。 - 初步方法：对已知蛋白家族，计算 ESM2 embedding 与 MD 模拟构象的映射关系；用 embedding 引导的初始构象作为 MD 或生成模型的起点。 - 验证方式：在标准蛋白（如 fast-folding 蛋白）上比较 embedding-guided 采样 vs 随机采样的构象覆盖率。 - 可能的失败模式：embedding 主要编码序列-结构关系而非动力学信息，可能无法捕获多构象状态。 - 创新状态：unverified

候选 2：结构感知的序列分类器——将 AlphaFold 预测结构作为分类特征 - 来源局限/观察：InterPro 将 AlphaFold 结构「整合」但未说明具体机制；结构信息可能显著提升功能位点预测精度。 - 核心假设：将 AlphaFold 预测结构的几何特征（如残基接触图、口袋形状）与序列 embeddings 联合输入分类器，能提升功能位点预测的 precision。 - 相对本文的增量：从「结构作为辅助验证」到「结构作为一等特征」。 - 初步方法：构建多模态分类器，输入 = ESM2 embedding + AlphaFold 结构几何特征（如 GVP 或 SchNet 编码），输出 = InterPro entry/功能位点。 - 验证方式：在 InterPro 基准上对比「序列-only」vs「序列+结构」的精度差异，重点关注此前无法注释的序列。 - 可能的失败模式：AlphaFold 对远源同源蛋白的预测结构可能不可靠，引入噪声。 - 创新状态：unverified

候选 3：MCP server 驱动的蛋白质结构分析工作流 - 来源局限/观察：InterPro 的 MCP server 是 AI 可访问数据库的早期实践；类似协议可扩展到结构数据库和 MD 轨迹分析。 - 核心假设：通过 MCP 协议将 PDB/AlphaFold DB/MD 轨迹接入 LLM，可实现自然语言驱动的结构分析（如「找出所有与 ATP 结合的 pocket 并比较构象差异」）。 - 相对本文的增量：从「查询注释」到「查询+分析+推理」的完整 AI 工作流。 - 初步方法：开发「StructureMCP」server，封装 PDB 查询、结构比对（TM-align）、口袋检测（FPocket）等工具，通过 MCP 暴露给 LLM。 - 验证方式：设计一组结构分析任务（如「比较 kinase 家族 ATP 口袋的构象多样性」），评估 LLM+MCP 的完成质量 vs 人工分析。 - 可能的失败模式：LLM 可能生成看似合理但错误的推理链，需要结构化验证机制。 - 创新状态：unverified

候选 4：覆盖率-精度权衡的显式建模——深度学习分类器的校准 - 来源局限/观察：InterPro-N 追求覆盖率但未报告精度；类似问题在结构预测中普遍存在（如 AlphaFold pLDDT 的校准）。 - 核心假设：InterPro-N 的预测置信度与真实精度存在系统性偏差，可通过 temperature scaling 或 conformal prediction 校准。 - 相对本文的增量：为 InterPro-N 提供可靠的 uncertainty quantification，使下游用户能根据置信度过滤注释。 - 初步方法：收集 InterPro-N 预测的置信度分数与人工验证标签，拟合校准曲线；应用 conformal prediction 生成覆盖率保证的预测集。 - 验证方式：在 Swiss-Prot 人工注释子集上评估校准后的覆盖率-精度曲线。 - 可能的失败模式：校准需要大量人工验证标签，成本高。 - 创新状态：unverified
