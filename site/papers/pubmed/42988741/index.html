ECOD in 2027: a modernized interface and an updated classification of protein domains.

Schaeffer, R Dustin; Roy, Barsha; Guo, Rui; Cong, Qian; Medvedev, Kirill E; Grishin, Nick V
Nucleic acids research · 2026-11-05 · 仅摘要 · 原文

该文介绍ECOD蛋白结构域进化分类数据库的更新，涉及结构预测模型分类和结构搜索，但主要是数据库资源建设而非方法创新，与蛋白质结构计算课题相关但贡献有限。

摘要

The Evolutionary Classification of Domains (ECOD) organizes protein domains into a hierarchy of evolutionary relationships, encompassing both experimentally determined and computationally predicted structures. ECOD now classifies 2.9M domains, of which approximately 1.37M derived from the Protein Data Bank and 1.51M from predicted models in the AlphaFold Protein Structure Database. The principal development we report here is a complete rebuild of the ECOD web resource. Search has been reconstructed around three modalities: (i) sequence, (ii) structure, and (iii) keyword. Foldseek now is the primary search method for the ECOD web page, searching a approximately 457k representative domain database that is also distributed for local use. Results are presented through a Mol* interactive viewer, and a new API has been developed for programmatic access to the database. Alongside the interface, the pipeline for classifying new PDB entries has been rebuilt and returned to a regular cadence, family groups have been synchronized with Pfam v38.2, the bulk distributables have been reorganized and now include the search databases, the ligands in contact with each domain are recorded for experimental structures and annotated with drug cross-references from DrugDomain, and a registry has been introduced through which ECOD assigns stable identifiers to gene-called proteins and records the structures it predicts. ECOD is freely available at http://prodata.swmed.edu/ecod.

摘要翻译

结构域进化分类（ECOD）将蛋白质结构域组织成语义进化关系的层级结构，涵盖实验确定和计算预测的结构。ECOD目前分类了290万个结构域，其中约137万个来自蛋白质数据银行（Protein Data Bank），151万个来自AlphaFold蛋白质结构数据库中的预测模型。我们在此报告的主要进展是对ECOD网络资源的全面重建。搜索已围绕三种模式重构：（i）序列，（ii）结构，以及（iii）关键词。Foldseek现为ECOD网页的主要搜索方法，搜索约45.7万个代表性结构域数据库，该数据库也分发给本地使用。结果通过Mol*交互式查看器呈现，并开发了新API以支持对数据库的程序化访问。除界面外，用于分类新PDB条目的流程已重建并恢复定期节奏，家族组已与Pfam v38.2同步，批量分发文件已重组并现包含搜索数据库，每个结构域接触的配体已记录于实验结构，并附有来自DrugDomain的药物交叉引用注释，同时引入注册系统，通过该系统ECOD为基因命名蛋白质分配稳定标识符并记录其预测的结构。ECOD可在http://prodata.swmed.edu/ecod免费获取。

03 研究问题

  • 具体问题：如何将 ECOD 这一蛋白质结构域进化分类数据库从「以实验结构为主、手动维护」的旧模式，升级为「覆盖实验+预测结构、自动化流水线、现代 web 交互」的可持续资源？
  • 为什么重要：AlphaFold DB 带来了海量预测结构，传统人工分类无法跟上规模；同时旧版 ECOD web 界面搜索能力有限，无法满足社区对结构搜索、程序化访问、配体注释的需求。
  • 现有方法为何不足：SCOP 依赖人工 curation，更新慢；CATH 虽有自动化但层级定义与 ECOD 的进化视角不同；旧 ECOD 界面仅支持序列搜索，无结构搜索，无 API，分类流水线中断。
  • 精确研究问题：Can a domain classification resource be rebuilt to handle millions of predicted structures while maintaining evolutionary hierarchy quality and providing modern search/access modalities?

06 核心思想

  1. 表面方法：重建 ECOD web 资源——三种搜索模态（序列/结构/关键词）、Foldseek 主搜索、Mol* 可视化、新 API；重建分类流水线；同步 Pfam；记录配体互作；引入基因命名蛋白注册表。

  2. 核心洞察：结构域分类资源的核心价值不在于「分类本身」，而在于「可搜索性 × 可编程访问 × 与外部资源（Pfam、DrugDomain、AlphaFold DB）的互操作」。将预测结构纳入分类不是简单的「数量扩展」，而是需要重新设计代表集（45.7 万代表域）和搜索策略（Foldseek）来应对规模。

  3. 可能的普适教训 [Analysis]：对于任何蛋白质结构相关计算资源，当数据规模从「千级」跃升到「百万级」时，瓶颈往往不在分类算法本身，而在「检索效率 × 可视化 × API 设计 × 与外部数据库的同步机制」。ECOD 2027 的更新模式（搜索模态重构 + 代表集 + 流水线自动化）可迁移到其他结构资源（如 CATH、SCOP 的现代化改造）。

07 方法总览

  • 输入：PDB 实验结构 + AlphaFold DB 预测结构；Pfam v38.2 家族分组；DrugDomain 配体注释
  • 输出：ECOD 分类层级（archi > topology > homologous family > sequence family）；web 界面；API；批量下载文件（含搜索数据库）
  • 模块： 1. 分类流水线（PDB 新条目 → 结构域划分 → 层级分配） 2. 搜索系统（序列搜索 + Foldseek 结构搜索 + 关键词搜索） 3. 可视化（Mol* 交互式查看器） 4. API（程序化访问） 5. 配体注释模块（实验结构配体 + DrugDomain 药物交叉引用） 6. 注册表（基因命名蛋白的稳定标识符）
  • 训练：不适用（非机器学习方法）
  • 工具：Foldseek（结构搜索）、Mol*（可视化）、Pfam（家族同步）、DrugDomain（配体注释）
  • 假设：预测结构（AlphaFold）的域划分可信度足以纳入进化分类；Foldseek 搜索的敏感度足以替代传统 DALI/SSAP 等结构比对
  • 流程：PDB/AlphaFold 结构 → 结构域划分 → 与已有层级比对 → 分配 archi/topology/HF/SF → 记录配体互作 → 纳入搜索数据库 → 通过 web/API 提供访问

11 结论正确解读

  • 任务范围：本文结论仅限于「ECOD 数据库的更新内容描述」，不涉及分类方法学的创新验证。
  • oracle/真值输入：分类的「真值」为 ECOD 自身的进化层级定义（archi/topology/HF/SF），无外部独立验证。
  • 端到端状态：分类流水线已重建并恢复定期运行，但未提供端到端的时间/资源消耗数据。
  • 算力成本：未提供。
  • 历史数据依赖：分类依赖 PDB 和 AlphaFold DB 的既有结构数据；家族分组依赖 Pfam v38.2。
  • 模型依赖：依赖 AlphaFold 预测结构的质量（未讨论预测误差对分类的影响）。
  • 最难情形：预测结构中的域边界划分错误、低置信度区域（pLDDT 低）的域分配问题未讨论。
  • 群体/领域边界：ECOD 面向结构生物学、进化生物学、蛋白质设计社区；结论不适用于其他分子类型。
  • 不确定性：未提供分类一致性/错误率估计。

有边界的复述：ECOD 在 2027 年更新中成功将分类规模扩展至 290 万结构域（含 151 万 AlphaFold 预测结构域），重建了 web 界面（三种搜索模态 + API + Mol* 可视化），并恢复了 PDB 新条目的定期分类。这些更新在功能层面是成立的；但本文未提供分类质量、搜索精度、配体注释覆盖率等量化验证，因此不能据此判断 ECOD 2027 的分类准确性优于或等同于旧版。

14 学到什么

Agent 提炼的知识候选：

  1. 结构域代表集策略：ECOD 从 290 万域中构建 45.7 万代表集用于 Foldseek 搜索——这是「大规模结构资源 × 搜索效率」的通用方案。可迁移到：任何需要结构相似性搜索的蛋白质设计/对接场景，先聚类代表集再搜索，再映射回全集。

  2. Foldseek 作为结构搜索主引擎：Foldseek 的 3Di 字母表编码 + 预索引，使百万级结构搜索在秒级完成。可迁移到：蛋白质构象采样中的「构象去重」——用 Foldseek 对 MD 模拟轨迹或采样构象做快速相似性聚类。

  3. 配体-结构域互作注释流程：ECOD 记录每个结构域接触的配体，并交叉引用 DrugDomain 药物注释。可迁移到：蛋白质-配体对接研究中，用 ECOD 的域-配体注释作为「已知结合位点」的先验，辅助对接 pose 筛选。

  4. 分类流水线的「定期节奏」设计：ECOD 重建了 PDB 新条目的定期分类流水线。可迁移到：蛋白质设计工作流中，对「新生成结构」的自动分类/验证环节——设计一个自动化的「结构 → 域划分 → 功能注释」pipeline。

  5. 基因命名蛋白注册表：ECOD 为基因命名蛋白分配稳定标识符，连接基因-蛋白-结构。可迁移到：蛋白质设计项目中，建立「设计序列 → 结构 → 功能注释」的统一标识体系，便于跨实验追踪。

  6. 三种搜索模态的互补设计：序列（传统）、结构（Foldseek）、关键词（注释文本）并行。可迁移到：蛋白质构象数据库的检索界面设计——用户可能从序列、结构、或功能描述三个入口出发。

15 与已有知识连接

  • SCOP / CATH：ECOD 与 SCOP、CATH 并列为三大结构域分类数据库。ECOD 的独特之处在于「进化层级」（archi/topology 反映进化事件而非纯几何折叠）。本文未与 SCOP/CATH 做直接比较，但领域共识是 ECOD 更侧重进化同源性。可参考：Andreeva et al. (SCOP2)、Sillitoe et al. (CATH) 的更新论文。
  • AlphaFold DB：ECOD 2027 将 151 万预测结构域纳入分类，这是对 AlphaFold DB（Varadi et al., 2022, NAR）产出的直接消费。可迁移：AlphaFold 预测结构的「域划分」是下游分析的关键预处理步骤。
  • Foldseek：van Kempen et al., 2023, Nature Biotechnology。Foldseek 的 3Di 编码是结构搜索的 SOTA 方法，ECOD 采用它作为主搜索工具验证了其在大规模资源中的实用性。
  • Pfam：Mistry et al., 2021, NAR。ECOD 家族分组与 Pfam v38.2 同步，说明 Pfam 的家族定义仍是领域内的「金标准」之一。
  • DrugDomain：未提供具体引用，但该资源将 PDB 配体与药物信息关联，与 DrugBank（Wishart et al., 2018）有概念重叠。
  • Mol：Sehnal et al., 2021, NAR。Mol 是当前结构可视化的主流 web 组件，ECOD 采用它符合领域趋势。

16 研究想法

Agent 生成的研究候选：

  1. 候选名称：AlphaFold 结构域的 ECOD 分类质量审计 - 来源局限/观察：ECOD 2027 将 151 万 AlphaFold 域纳入分类，但未报告分类质量；预测结构的域边界可能系统性偏差。 - 核心假设：AlphaFold 预测结构的域划分在低 pLDDT 区域（loop、domain linker）存在系统性错误，导致 ECOD 层级分配偏差。 - 相对本文的增量：本文只报告数量，不报告质量；此研究提供首个大规模质量审计。 - 初步方法：选取 ECOD 中同时有实验结构和 AlphaFold 预测结构的域对，比较域边界一致性；用 pLDDT 分层分析错误率；对不一致案例做人工审查。 - 验证方式：与 SCOP/CATH 对同一结构的域划分做三方比较；计算域边界 IoU。 - 可能的失败模式：AlphaFold 域划分与实验结构高度一致（假设被证伪），或差异无系统性模式。 - 创新状态：unverified

  2. 候选名称：Foldseek 驱动的构象空间去重与聚类 - 来源局限/观察：ECOD 用 Foldseek 搜索 45.7 万代表域，证明其在大规模结构集合上的效率；MD 模拟和构象采样产生海量构象，缺乏快速去重工具。 - 核心假设：Foldseek 的 3Di 编码可用于 MD 轨迹构象的快速聚类，且聚类结果与 RMSD 聚类高度一致，但速度快 2-3 个数量级。 - 相对本文的增量：将 ECOD 的「代表集 + Foldseek」模式迁移到构象采样场景。 - 初步方法：对 MD 模拟轨迹（如泛素、激酶）提取构象，用 Foldseek all-vs-all 计算相似性，与 RMSD 聚类比较；测试不同 3Di 阈值与 RMSD 阈值的对应关系。 - 验证方式：聚类纯度、稳定性（bootstrap）；与经典聚类（如 GROMOS 算法）比较。 - 可能的失败模式：3Di 编码对构象细微差异不敏感，聚类过粗；或 3Di 对局部构象变化（如 loop 运动）过度敏感。 - 创新状态：unverified

  3. 候选名称：ECOD 域-配体注释作为对接先验的基准测试 - 来源局限/观察：ECOD 记录了实验结构的域-配体接触，并交叉引用 DrugDomain 药物注释；但未验证这些注释在对接场景中的实用性。 - 核心假设：ECOD 的域-配体注释可作为「已知结合位点」先验，显著提升分子对接的 pose 筛选准确率（尤其对 apo 结构或预测结构）。 - 相对本文的增量：将静态注释转化为可操作的对接先验。 - 初步方法：从 ECOD 提取域-配体对，构建基准集；对 apo 结构或 AlphaFold 预测结构做对接，用 ECOD 注释过滤 pose；与无先验对接比较 Top-1 成功率。 - 验证方式：在 DUD-E 或 Astex 子集上比较；与 PocketMiner/DeepSite 等口袋预测方法对比。 - 可能的失败模式：ECOD 注释覆盖不全，或域-配体接触不代表「可成药口袋」。 - 创新状态：unverified

  4. 候选名称：进化层级约束的蛋白质设计序列生成 - 来源局限/观察：ECOD 的 archi/topology 层级反映进化事件，但现有蛋白质设计方法（如 RFdiffusion、ProteinMPNN）不感知进化层级。 - 核心假设：将 ECOD 的进化层级作为条件约束，可引导设计序列/结构偏向特定进化谱系，提高设计结构的可折叠性和功能多样性。 - 相对本文的增量：将分类资源从「分析工具」升级为「设计约束」。 - 初步方法：在 ProteinMPNN 或 ESM-IF 中引入 ECOD topology 的 one-hot 或 embedding 条件；在特定 topology 的天然序列上微调；生成序列后折叠验证。 - 验证方式：设计序列的 ECOD 分类一致性；AlphaFold2 预测结构与设计结构的 RMSD；表达实验（如有条件）。 - 可能的失败模式：进化层级信息与序列-结构关系冗余，条件化无增益；或层级约束过强，限制序列多样性。 - 创新状态：unverified

  5. 候选名称：ECOD 分类驱动的 MD 模拟初始结构选择 - 来源局限/观察：ECOD 对同一 topology 下多个结构域的分类，隐含了「同一进化谱系内结构多样性」的信息；MD 模拟的初始结构选择常依赖人工经验。 - 核心假设：从 ECOD 同一 topology 中选取「代表性结构域」作为 MD 初始结构，比随机选取或单一晶体结构更能覆盖构象空间。 - 相对本文的增量：将分类信息用于模拟采样策略。 - 初步方法：选取若干 topology（如 kinase fold、TIM barrel），从 ECOD 中提取同 topology 多结构域；分别做短 MD；比较构象空间覆盖度（如 PCA 投影面积、RMSF 分布）。 - 验证方式：与单结构长模拟的构象覆盖比较；增强采样（如 GaMD、REMD）下的表现。 - 可能的失败模式：同 topology 结构域间序列差异大，MD 力场参数化不一致；或构象覆盖差异不显著。 - 创新状态：unverified
