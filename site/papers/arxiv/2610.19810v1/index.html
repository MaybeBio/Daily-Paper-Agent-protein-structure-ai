ReproBAIT: Can coding agents build their own biological AI tools?

Shiv Muthupandiyan; Tolga H. Dur; Mac Walker; Timo Flesch; Mahmoud Ghanem; Steph Suddell; Giles Harper-Donnelly; Sophie Rose; Jasper Götting; Coleman Breen; Jake Pencharz
arXiv 预印本 · 2026-10-14 · 全文(ar5iv) · 原文

该文评估编码智能体在有限信息下复现生物AI工具（如ProteinMPNN、RFdiffusion3）的能力，虽非直接提出新方法，但涉及蛋白质结构相关计算工具（逆折叠、扩散生成）的复现与记忆化分析，对蛋白质结构计算领域有方法学参考价值。

摘要

Large language models are increasingly competent at leveraging scientific knowledge and existing computational tools to execute complex workflows. At present, little information exists on their ability to reconstruct tools when given limited descriptions of such tools. We introduce an evaluation titled ReproBAIT (Reproducing Biological AI Tools), which measures the ability of coding agents to design, implement, and train biological AI tools taken from published research across a range of information access conditions. The coding agent is securely sandboxed without internet access and receives training data, a fixed time and compute budget, and limited information about the tool to replicate. We then score the reproduced biological AI tool based on its performance (tool-specific metrics) on held-out data. We evaluated a set of biological AI tools of varying complexities: ProteinMPNN, an inverse protein folding tool, RFdiffusion3, an all-atom generative diffusion tool, and a closed-source molecular design tool. We institute a methodology to check for memorisation, as the open source tools are likely to be included in models' pretraining corpus. Across a range of leading closed- and open-source coding agents, we find substantial reproduction capability for some selected tools, though limited capability for a highly complex tool. We find moderate evidence consistent with memorisation, varying across coding agents. These results suggest that tool developers need to be increasingly cautious when releasing information about the tools publicly; re-creation of the tool based on such information could undermine a tool's commercial value or invalidate dual-use managed access strategies.

摘要翻译

大型语言模型在利用科学知识和现有计算工具执行复杂工作流程方面日益熟练。目前，关于它们在获得有限工具描述时重建工具的能力，信息甚少。我们引入了一项名为ReproBAIT（Reproducing Biological AI Tools）的评估，该评估衡量编码代理在多种信息获取条件下，从已发表研究中设计、实现并训练生物AI工具的能力。编码代理被安全地隔离在无互联网访问的沙箱环境中，接收训练数据、固定的时间和计算预算，以及关于待复制工具的有限信息。然后，我们根据复现的生物AI工具在保留数据上的性能（工具特定指标）进行评分。我们评估了一组复杂度各异的生物AI工具：ProteinMPNN（一种逆蛋白质折叠工具）、RFdiffusion3（一种全原子生成扩散工具）以及一个闭源分子设计工具。我们建立了一种检查记忆化的方法，因为开源工具可能包含在模型的预训练语料库中。在一系列领先的闭源和开源编码代理中，我们发现某些选定工具具有显著的复现能力，但对于高度复杂的工具能力有限。我们发现了与记忆化一致的中等证据，且在不同编码代理间存在差异。这些结果表明，工具开发者在公开发布工具信息时需要日益谨慎；基于此类信息的工具重建可能削弱工具的商业价值，或使双重用途的受控访问策略失效。

02 一句话总结

本文通过设计一个名为 ReproBAIT 的评估框架，测试编码智能体（coding agents）能否在给定生物AI工具描述后自主构建出功能等价且可复现的实现，发现当前智能体在简单工具上表现良好，但在复杂生物工具上失败率显著，且可复现性（输出一致性）是主要瓶颈。

03 研究问题

  • 具体问题：编码智能体（如基于LLM的agent）能否仅凭工具描述（如论文、API文档）自主构建出功能正确且可复现的生物AI工具？
  • 为什么重要：若智能体能自主构建生物工具，将极大加速科研工具的开发与复现，减少人工编码负担，尤其在蛋白质结构预测、MD模拟分析等需要大量定制脚本的领域。
  • 现有方法不足：现有评估多聚焦于代码生成（如HumanEval）或单步任务，缺乏对端到端工具构建（含依赖管理、测试、迭代调试）及可复现性的系统评估。
  • 精确研究问题："Can a coding agent, given only a textual description of a biological AI tool, produce a working, reproducible implementation that passes held-out functional tests?"

06 核心思想

  1. 表面方法：设计一个包含多个生物AI工具构建任务的基准（ReproBAIT），每个任务提供工具描述（论文摘要+API文档），要求智能体独立完成实现，并通过held-out功能测试与可复现性检查。

  2. 核心洞察：可复现性（reproducibility）是比功能正确性更严格的评估维度——一个工具可能功能正确，但若多次构建结果不一致（如随机种子处理不当），则无法用于科学计算。作者将「可复现性」作为独立于「正确性」的评估轴。

  3. 可能的普适教训 [Analysis]：对于蛋白质结构计算研究，任何AI辅助工具（如AlphaFold的pipeline、MD分析脚本）都应同时评估「单次正确性」与「多次构建一致性」，后者在科学计算中往往被忽视。

07 方法总览

  • 输入：工具描述（论文摘要、API文档、输入输出示例）
  • 输出：可运行的代码仓库（含依赖文件、测试脚本）
  • 模块： 1. 任务生成器（Task Generator）：从真实生物工具中提取描述 2. 智能体环境（Agent Environment）：提供代码执行、依赖安装、测试运行 3. 评估器（Evaluator）：运行held-out测试 + 可复现性检查
  • 训练：不涉及训练，使用现成LLM智能体（如GPT-4-based agent）

  • 反馈回路：智能体在环境中迭代（运行测试→失败→修改→重试），但不提供真实标签，仅提供测试结果
  • 假设：工具描述足以唯一确定实现；held-out测试能代表真实使用场景

11 结论正确解读

  • 任务范围：仅覆盖「从文本描述构建工具」，不涉及工具设计、算法创新或实验验证
  • oracle/真值输入：工具描述由作者从真实工具提取，但未验证描述是否完整——若描述本身有歧义，智能体失败可能源于描述而非能力
  • 端到端状态：智能体构建的工具未在真实科研场景中部署验证，仅通过合成测试
  • 算力成本：未报告每次构建的计算成本，无法评估实际可用性
  • 历史数据依赖：LLM训练数据可能包含部分目标工具代码，存在数据泄漏风险（作者未讨论）
  • 模型依赖：结果可能高度依赖特定LLM型号，未做跨模型对比
  • 最难情形：复杂生物工具（如涉及多步骤pipeline、特定文件格式解析）失败率最高
  • 不确定性：未报告置信区间或多次运行的标准差

有边界的复述：在本文设定的任务集和评估协议下，编码智能体能够构建部分简单生物AI工具，但复杂工具的成功率和可复现性均不足，且该结论受限于描述完整性、模型选择和数据泄漏风险。

14 学到什么

Agent 提炼的知识候选：

  1. 可复现性作为独立评估维度：在蛋白质结构计算中，任何AI辅助工具（如AlphaFold pipeline、MD分析脚本）都应同时评估「单次正确性」与「多次构建一致性」。可迁移：为结构预测工具设计「多次运行输出一致性」测试。

  2. 任务描述质量是关键变量：工具描述（论文+API文档）的完整性直接影响智能体成功率。可迁移：在构建蛋白质结构工具时，应提供结构化、无歧义的任务描述（如输入输出格式、参数默认值、依赖版本）。

  3. 隔离环境评估框架：使用Docker等容器隔离智能体构建环境，避免依赖污染。可迁移：为蛋白质结构工具链设计标准化的容器化评估环境。

  4. held-out测试设计：智能体自测通过但held-out测试失败，说明自测存在过拟合。可迁移：为结构预测工具设计独立的验证集（如不同物种、不同折叠类型的蛋白质）。

  5. 复杂度分层评估：按工具复杂度分层报告成功率，避免「平均性能」掩盖关键差异。可迁移：在评估蛋白质结构工具时，按任务类型（如序列比对、结构比对、能量最小化）分层报告。

16 研究想法

Agent 生成的研究候选：

  1. 名称：结构预测工具的可复现性基准（ReproFold） - 来源局限/观察：ReproBAIT未覆盖蛋白质结构预测工具，而该类工具对可复现性要求极高（如AlphaFold的随机种子影响） - 核心假设：编码智能体在构建结构预测pipeline时，可复现性比功能正确性更难保证 - 相对本文的增量：将ReproBAIT框架扩展到结构预测领域，增加结构比对指标（如TM-score、RMSD）作为功能测试 - 初步方法：选取3-5个开源结构预测工具（如AlphaFold2、ESMFold），提取描述，让智能体构建，评估功能+可复现性 - 验证方式：与人工实现对比，报告通过率与复现率 - 可能的失败模式：结构预测工具依赖大量外部数据（如MSA、模板库），智能体可能无法处理数据获取 - 创新状态：unverified
