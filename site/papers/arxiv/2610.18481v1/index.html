ProTok: Unified Protein Tokenization via Modular Multi-Codebook Quantization

Romain Hardy; Xiaoman Zhang; Pranav Rajpurkar
arXiv 预印本 · 2026-10-13 · 全文(ar5iv) · 原文

ProTok提出一种统一的多模态蛋白质分词器，通过多码本量化将序列、结构和功能映射到共享离散词汇表，在结构重建、功能检索和序列-结构联合生成上均优于基线，直接服务于蛋白质结构计算与生成建模。

摘要

Protein sequence, structure, and functional annotations each capture complementary aspects of protein biology, yet existing tokenizers encode each modality independently, limiting the expressiveness of discrete protein representations. We present ProTok, a unified protein tokenizer that maps all three modalities into a modular discrete vocabulary via product quantization with per-modality codebook groups and modality dropout. A single ProTok checkpoint supports flexible inference from any modality subset without retraining. On seven StructTokenBench benchmarks spanning 14 tasks and 28 test splits, ProTok achieves an average rank of 1.4 across all structure-only tokenizers, placing first on 21 splits and among the top two on 27 of the 28. These gains come without sacrificing reconstruction: ProTok's tokens reach 0.939 lDDT on CATH 4.2, showing that multi-codebook quantization and multi-modal training yield tokens that are both reconstructable and informative. ProTok's structure tokens further lead all baseline structure tokenizers on zero-shot functional retrieval across CATH, Enzyme Commission, and Gene Ontology label hierarchies. The vocabulary also supports generation: a compact language model trained from scratch over ProTok tokens jointly generates backbone and sequence, with 52% of sampled backbones designable versus 21% for a parameter-matched GeoBPE baseline. ProTok shows that structure, sequence, and function can share one discrete vocabulary, motivating protein language models that reason over a unified token stream.

摘要翻译

蛋白质序列、结构及功能注释各自捕捉了蛋白质生物学的互补方面，然而现有分词器独立编码每种模态，限制了离散蛋白质表示的表达能力。我们提出ProTok，一种统一的蛋白质分词器，通过乘积量化（product quantization）结合每模态码本组和模态丢弃（modality dropout），将全部三种模态映射到模块化离散词汇表中。单个ProTok检查点支持从任意模态子集进行灵活推理，无需重新训练。在涵盖14项任务和28个测试分割的七个StructTokenBench基准上，ProTok在所有仅结构分词器中达到平均排名1.4，在21个分割中位列第一，并在28个中的27个分割中跻身前两名。这些提升并未以牺牲重建为代价：ProTok的令牌在CATH 4.2上达到0.939 lDDT，表明多码本量化和多模态训练产生的令牌既可重建又具信息性。ProTok的结构令牌在CATH、酶委员会（Enzyme Commission）和基因本体（Gene Ontology）标签层级上的零样本功能检索中，进一步领先所有基线结构分词器。该词汇表还支持生成：一个从零开始在ProTok令牌上训练的紧凑语言模型联合生成骨架和序列，其中52%的采样骨架可设计，而参数匹配的GeoBPE基线仅为21%。ProTok表明结构、序列和功能可以共享一个离散词汇表，激励了在统一令牌流上进行推理的蛋白质语言模型。

02 一句话总结

本文提出 ProTok，一种基于模块化多码本量化（modular multi-codebook quantization）的统一蛋白质 tokenization 框架，通过将蛋白质的不同特征维度（如序列、结构）分配到独立码本进行离散编码，以生成信息更丰富、更灵活的 token 表示，从而提升下游蛋白质计算任务的性能。

03 研究问题

  • 具体问题：如何设计一种统一的蛋白质 tokenization 方法，能够同时有效地编码蛋白质的多种信息（如序列、结构、功能），并生成信息量丰富、可扩展的离散表示，以支持多种下游任务（如结构预测、构象生成、蛋白质设计）？
  • 为什么重要：Tokenization 是连接原始生物数据与深度学习模型的基石。现有的蛋白质 tokenization 方法（如基于序列的 k-mer、基于结构的几何 token）通常只关注单一信息源，且使用单一码本，导致表示能力有限，难以捕捉蛋白质的多层次特性，限制了下游模型的性能。
  • 现有方法为何不足：单一码本量化（如 VQ-VAE）在编码高维、多模态蛋白质数据时，容易导致码本崩溃（codebook collapse）或信息瓶颈，无法有效解耦不同特征。此外，现有方法缺乏模块化设计，难以针对不同任务或数据类型进行灵活扩展和定制。
  • 精确研究问题：Can a modular multi-codebook quantization framework provide a more expressive and flexible discrete tokenization for proteins, leading to improved performance on downstream protein structure-related tasks compared to single-codebook or sequence-only baselines?

04 背景与发展脉络

（注：此脉络基于本文框架及领域常识构建，标注为「经外部核验」的部分为领域公认事实。）

  1. 阶段一：基于序列的 tokenization（经外部核验）

    • 代表方法：k-mer、BPE（Byte-Pair Encoding）、单氨基酸 token。
    • 优点：简单、计算高效，适用于序列模型（如 Transformer）。
    • 局限：完全忽略结构信息，无法捕捉空间邻近性和几何约束。

  2. 阶段二：基于结构的 tokenization（经外部核验）

    • 代表方法：基于残基几何（如距离矩阵、角度）、基于二级结构（SSE）的 token，或使用 VQ-VAE 对结构片段进行离散编码。
    • 优点：引入结构信息，对结构预测和生成任务更友好。
    • 局限：通常只关注单一结构表示，缺乏与序列信息的统一；单一码本容量有限，难以编码多样化的结构 motif。

  3. 阶段三：统一多模态 tokenization（本文主张的位置）

    • 代表方法：ProTok（本文）。
    • 优点：通过模块化多码本设计，将序列、结构等不同信息源分配到独立码本，实现信息解耦和灵活组合，旨在统一序列与结构表示。
    • 局限：作为新方法，其计算开销、码本规模选择、以及在不同任务上的泛化能力仍需验证。

06 核心思想

  1. 表面方法：ProTok 使用多个独立的码本（codebooks），每个码本负责编码蛋白质的一种特定特征（如一个码本编码序列模式，另一个编码结构 motif）。输入蛋白质通过一个编码器被映射到多个潜变量，每个潜变量被量化到其对应的码本中，最终生成一组离散 token 的集合。

  2. 核心洞察：蛋白质的不同信息维度（序列、结构）在本质上是解耦的，但又是互补的。通过模块化多码本设计，可以显式地解耦这些信息，让每个码本专注于学习一种特定的表示，从而避免单一码本需要同时编码所有信息而导致的容量不足和特征纠缠问题。这种设计也提供了灵活性，可以针对不同任务选择或组合不同的码本。

  3. 可能的普适教训 [Analysis]：对于复杂生物数据的表示学习，显式地解耦信息源并模块化处理，可能比使用一个巨大的、隐式的单一表示空间更有效。这类似于在多模态学习中，使用独立的编码器处理不同模态，再在后期融合，往往优于早期融合。此思想可迁移到其他需要多维度特征融合的蛋白质计算任务中。

07 方法总览

（注：由于仅提供摘要，以下流程基于摘要描述和领域通用方法进行合理推断，具体细节需查阅原文。）

  • 输入：蛋白质序列（可能包含结构信息，如 PDB 结构或预测结构）。
  • 输出：一组离散的 token 序列（或 token 集合），每个 token 对应一个码本中的一个条目。
  • 核心模块：
    1. 编码器（Encoder）：将输入的蛋白质（序列+结构）映射为多个潜向量（latent vectors）。
    2. 模块化多码本（Modular Multi-Codebooks）：包含多个独立的码本，每个码本包含若干可学习的嵌入向量。
    3. 量化器（Quantizer）：将每个潜向量映射到其对应码本中最近的嵌入向量，得到离散 token。
    4. 解码器（Decoder，可选）：用于从离散 token 重建输入，以训练整个框架（类似 VQ-VAE）。
  • 训练：通过最小化重建损失（reconstruction loss）和码本损失（codebook loss）来端到端训练。
  • 假设：假设模块化多码本能够比单一码本更有效地捕捉蛋白质的多层次特征，且这些离散 token 对下游任务有益。
  • 文字流程：输入蛋白质 → 编码器提取多维度特征 → 生成多个潜向量 → 每个潜向量被独立量化到其专属码本 → 输出一组离散 token → （可选）解码器重建输入用于训练 → 下游任务使用这些 token。

11 结论正确解读

  • 任务范围：本文提出的是一种通用的 tokenization 方法，其结论应限定在“离散表示学习”这一任务范畴内。
  • Oracle/真值输入：未提供。若下游任务涉及结构预测，则可能使用真实结构作为训练目标。
  • 端到端状态：ProTok 本身是一个表示学习框架，其“端到端”是指从原始输入到离散 token 的映射。下游任务（如结构预测）是否端到端使用这些 token，取决于具体实现。
  • 算力成本：未提供。多码本设计可能增加参数量和计算开销。
  • 历史数据依赖：依赖于训练数据的分布。若训练数据偏向某些蛋白质家族，则 tokenizer 的泛化能力可能受限。
  • 模型依赖：性能高度依赖于编码器、解码器的架构和训练策略。
  • 最难情形：对于结构高度新颖或序列同源性极低的蛋白质，tokenizer 可能无法有效编码。
  • 不确定性：作为预印本，其结论尚未经过同行评审，且缺乏实验细节，不确定性较高。
  • 有边界的复述：ProTok 提出了一种模块化多码本量化框架，在理论上能够解耦蛋白质的不同信息源，但其实际性能、泛化能力和计算开销尚待实验验证。其结论不应被解读为“在所有蛋白质任务上优于所有现有方法”，而应理解为“在离散表示学习方面提供了一种新的、有潜力的设计思路”。

14 学到什么

Agent 提炼的知识候选

  1. 可迁移概念：模块化表示学习。将复杂的生物实体（如蛋白质）分解为多个独立的、可解释的表示空间（码本），每个空间负责一种属性。这可以迁移到蛋白质设计任务中，例如，一个码本编码结构骨架，另一个码本编码序列偏好，从而实现对结构和序列的独立采样和组合优化。
  2. 可迁移方法：多码本量化（Multi-Codebook Quantization）。该方法本身可直接应用于其他需要离散表示的蛋白质计算任务，如将分子动力学（MD）模拟的构象轨迹离散化为一系列状态 token，每个码本对应不同的构象特征（如主链二面角、侧链 rotamer）。
  3. 可迁移实验设计：解耦性验证。在设计多码本模型时，应设计实验验证码本是否真正解耦，例如通过分析每个码本激活的分布与特定生物属性的相关性。这为评估表示学习质量提供了新思路。
  4. 对结构预测的启示：ProTok 的 token 可以作为结构预测模型的输入或中间表示，提供比单一序列 token 更丰富的先验信息。其模块化设计可能有助于模型在不同结构层次（二级结构、三级结构）上进行更精细的预测。

15 与已有知识连接

  • 相似工作：与 VQ-VAE、VQ-GAN 等量化方法在思想上相似，但将其扩展到了多码本和蛋白质领域。与著名的蛋白质语言模型（如 ESM-2）的 tokenization 不同，ProTok 旨在融合结构信息，而 ESM-2 主要基于序列。
  • 组合方向：ProTok 的 token 可以与现有的蛋白质结构预测模型（如 AlphaFold 的 Evoformer）结合，作为额外的输入特征。也可以与扩散模型（Diffusion Models）结合，在离散 token 空间中进行构象生成。
  • 冲突观点：与“端到端学习连续表示”的主流趋势（如 AlphaFold 直接预测原子坐标）相比，ProTok 回归到离散表示，这可能被视为一种倒退。但其潜在优势在于离散表示的可解释性和模块化，以及更易于与基于文本或逻辑的推理方法结合。
  • 可迁移领域：其模块化多码本思想可迁移到其他生物分子（如 RNA、小分子）的表示学习中，甚至更广泛的图结构数据（如知识图谱）的嵌入学习中。

Agent 生成的研究候选

  1. 候选名称：基于 ProTok 的构象空间离散化与状态转移建模

    • 来源局限/观察：ProTok 的模块化设计适合编码静态结构，但蛋白质功能依赖于动态构象变化。MD 模拟产生连续轨迹，难以直接应用离散 token。
    • 核心假设：使用 ProTok 对 MD 模拟的构象进行 tokenization，可以将连续的构象空间映射为离散的状态空间，从而用马尔可夫链或 Transformer 对构象转移进行建模，预测蛋白质的折叠路径或构象 ensemble。
    • 初步方法：1) 用 ProTok 对 MD 轨迹中的每一帧进行编码，得到 token 序列；2) 统计 token 间的转移概率，构建构象状态转移图；3) 训练一个模型（如 Transformer）来预测下一个状态 token，从而生成新的、合理的构象轨迹。
    • 验证方式：在已知的构象变化蛋白（如激酶）上测试，比较生成的构象 ensemble 与 MD 模拟的 ensemble 在关键结构特征（如活性位点距离）上的分布是否一致。
    • 创新状态：unverified

  2. 候选名称：面向蛋白质设计的可解释码本编辑

    • 来源局限/观察：ProTok 的码本可能编码了有意义的生物特征（如一个码本对应某种二级结构 motif），但如何利用这些码本进行目标导向的设计尚不明确。
    • 核心假设：通过直接编辑或组合 ProTok 的码本条目，可以精确控制生成蛋白质的结构和功能属性。
    • 初步方法：1) 分析 ProTok 各码本条目与已知结构/功能注释（如 GO 术语、SCOP 分类）的关联性；2) 设计一个“码本编辑器”，根据目标属性（如“想要一个具有特定底物结合 pocket 的蛋白质”）激活或抑制特定的码本条目；3) 将编辑后的 token 输入到生成模型（如基于 token 的扩散模型）中，生成新的蛋白质序列。
    • 验证方式：设计一个酶，其活性位点具有预设的几何形状，通过码本编辑生成序列，并用结构预测工具（如 AlphaFold）和分子对接验证其结构和结合能力。
    • 创新状态：unverified

  3. 候选名称：ProTok 与 AlphaFold 的协同：增强的序列-结构联合表示

    • 来源局限/观察：AlphaFold 使用连续表示进行结构预测，而 ProTok 提供离散表示。两者各有优劣，但尚未有工作将它们结合。
    • 核心假设：将 ProTok 生成的离散结构 token 作为辅助输入注入 AlphaFold 的 Evoformer 模块，可以提供更明确的结构先验，从而提升预测精度，尤其是在多聚体或构象变化大的蛋白上。
    • 初步方法：1) 用 ProTok 对已知结构的蛋白质进行 tokenization，得到结构 token；2) 修改 AlphaFold 的输入嵌入层，将结构 token 的嵌入向量与 MSA 和模板特征拼接；3) 在标准数据集（如 CASP）上重新训练或微调，比较与基线 AlphaFold 的性能。
    • 验证方式：在 CAMEO 或 CASP 的盲测集上评估 LDDT 和 TM-score。
    • 创新状态：unverified
